### [P1] Park 외 2026 — *Robust MAPF Method for Obstacles and Environmental Changes in Factory Environments* (Sensors 26(13) 4139)

출처: https://pmc.ncbi.nlm.nih.gov/articles/PMC13363869/ (본문 전체 읽음, 그림 9~12 수치는 미확인). **우리와 발상이 가장 가깝다.**

| 항목 | 내용 (근거) |
|---|---|
| A. 무슨 일이 생기나 | 로봇이 **감지 반경 10 m 안에서 새 장애물**을 보거나 기존 장애물이 크게 바뀌면 재계획(3.1). 고정 장애물(구간을 계속 점유)과 **움직이는 장애물**(옆 구간으로 이동, "그 구간에 있다"만 모델링)(3.2, 4.1). 사라지는 장애물은 없음. 구간 통과 시 0~5초 지연을 시뮬레이션에 넣음(4.1). 작업을 마치면 **새 작업을 온라인으로 배정**(4.1) |
| 세계 모델 | 격자 지도를 **구간(segment) 그래프**(통로·교차점)로 바꿈(그림 1). 시간은 초 단위, 이산 탐색인지는 불명확. 충돌 규칙은 CBS의 칸·이동 충돌 + **Interval / Margin 충돌**(3.3). 맞바꾸기 규칙은 없음 |
| 처음 계획 | 같은 "guidance 기반 CBS 틀" 안에서(4.1). 별도 처음 계획 단계 설명은 불명확 |
| 규모 | 100 m × 100 m 공장 1개, 로봇 10~100대, 30분 시행 20회(4.1) |
| **B. 작업 시간** | **없음.** 목적지 도착 후 작업 시간, 작업 중 상태, 작업 중 로봇 고정 규칙 모두 없음. 작업 끝나면 새 작업(4.1) |
| **C. 누구를 다시** | **장애물이 있는 구간에 지금부터 20초 안에 들어갈 예정인 로봇**(3.4). 20초 = 한 구간(약 10 m)을 0.5 m/s로 지나는 평균 시간. → **경로가 장애물 칸·시각과 겹치는지가 아니라 "진입 시각 창"** 기준. 20초 뒤에 들어가는 로봇은 빠짐. 창이 앞쪽만인지 양쪽인지 불명확 |
| 나머지 로봇 | "영향 없는 로봇은 기존 경로 유지"(3.4). 제약으로 먼저 적는지, CBS 충돌 검사에 넣는지는 **불명확** |
| 다시 계획하는 로봇끼리 순서 | 없음(CBS로 함께) |
| **D. 실패하면** | **없음.** 실패 정의(경로 없음 / 충돌), 로봇 추가, 넓히기, 폴백(전체 재계획) 모두 설명 없음. 성공률 = 30초 안에 모든 로봇 경로를 찾은 시행 비율(4.2.1), **"100대까지 성공률 100%"** |
| 도달 확인 | 없음 |
| E. 엔진 | CBS 계열. 세 모듈: ① 장애물 지도 관리(3.2) ② 전략 계획기 — 고정 장애물 회피 궤적으로 구간 이동 지침 갱신, 양방향 구간의 **Safe Interval SI(s)**(식 1), 장애물 종류·수에 따른 **통행 여유 Δ(s) 0~5초**(식 2) ③ 영향받은 로봇 판별·선택적 재계획(3.4). 저수준 알고리즘 이름 없음. 대기 동작 있음(3.3) |
| F. 보장 | 완전성·최적성·전체 재계획 대비 보장 **없음**. 성공률은 실험 결과뿐 |
| G. 평가 | 비교 기준: 장애물 없는 CBS(상한), **kR-MAPF k=1~5초**. 지표: 성공률, flowtime, 재계획 시간, 1초 안에 끝난 비율. 100대: 우리(Park) 3,417.6 ms vs kR-MAPF k=1 5,220.8 / k=5 15,942.8 ms(약 79% 감소). flowtime k=5 대비 약 24% 감소. **다시 계획한 로봇 수, 늦어진 로봇 수, 계산 중 멈춤은 재지 않음**. 짝지은 비교 언급 없음 |
| **H. 우리와 다른 점** | ① 선택 기준: **20초 진입 창** vs 우리 **경로-장애물 칸·시각 겹침**. ② 나머지 로봇을 먼저 적는지 불명확 vs 우리 **고정 먼저(①) 명시 + 그 효과 측정**. ③ **실패 처리 없음** vs 우리 Tier 1(길 위의 로봇 구조) + 안전망. ④ 성공 보장 없음 vs 우리 **전체 재계획 이상 구조적 보장**. ⑤ **작업 시간 없음** vs 우리 근무표·작업 중 고정. ⑥ 엔진 CBS(구간 그래프, 연속 시간) vs 우리 PP + 시공간 A\*(격자). ⑦ 움직이는 장애물 다룸 vs 우리는 나타나 머무는 장애물만. ⑧ 지표: 다시 계획한 로봇 수·계산 중 멈춤 손해는 우리만 |

**6번 비교 기준(Park식)에 쓸 것**: 선택 = "장애물 칸을 지금부터 W스텝 안에 지나갈 로봇". W = 20초 ÷ (한 칸 시간). 실패 처리는 논문에 없으므로
"실패하면 바로 안전망(전체 재계획)"으로 둔다. 나머지 로봇 등록 순서는 논문이 불명확하므로 **원래 우선순위 순(섞어 등록)**과 **고정 먼저** 두 가지를 다 돌려
"Park식 + 고정 먼저"가 우리 C1 효과를 받는지 확인한다.

### [P2] Sanjay & Li 2026 — *Scalable Long-Horizon Planning with Staggered Updates for Lifelong MAPF* (arXiv 2608.06702, 방법 이름 PUSH)

출처: https://arxiv.org/html/2608.06702 (본문·부록 전체 읽음, 그림 수치 미확인). **작업 시간 + 작업 중 로봇 보호가 있다 — C3에 가장 가까운 연구.**

| 항목 | 내용 (근거) |
|---|---|
| A. 무슨 일이 생기나 | lifelong MAPF(목표 도착 → 새 목표). 재계획은 **로봇마다 타이머**(time2Replan이 0이 되거나 다음 동작이 대기면 큐에 넣음, 알고리즘 1의 11~12행). **예기치 않은 장애물·지연은 없음**(지도 고정) |
| 세계 모델 | 격자 그래프, 이산 시간, 칸 충돌 + 맞바꾸기 충돌(III). 처음 계획 = 모두 W스텝 제자리 대기(IV-A) |
| 규모 | random-32-32-20, sortation, warehouse-small/large, symbotic, delivery. 수천~1만 대(초록) |
| **B. 작업 시간** | **있음 — TCT(task completion time) T 스텝.** 목표에 도착하면 T스텝 동안 머문 뒤 새 목표를 받음(III-1). 모델은 "확률적이고 미리 모를 수 있음"이라고 하지만 실험은 **고정 T=20**(V-B), T∈{0,10,20} 비교(V-D) |
| 작업 중 판단 | **있음 — 집합 H0 = "지금 작업 중인 로봇"**(알고리즘 1의 4, 6~9행). 경로가 대기뿐이고 목표에 있으면 작업 시작 → H0에 넣음 |
| 작업 중 로봇을 움직이나 | **절대 안 움직임** — H0는 보호 집합 H에 들어가 "재계획 중 밀 수 없음"(IV-B) |
| 작업 끝난 뒤 | 스케줄러가 **새 목표를 줌**(III). 주차·비켜 주기 없음 |
| 작업 시간 효과 장면 | T=0/10/20을 바꿔 처리량 비교(V-D). "작업 중 로봇이 우회로를 막는 장면"을 따로 만들지는 않음 |
| **C. 누구를 다시** | 타이머가 0이 된 로봇 + 다음 동작이 대기인 로봇(알고리즘 1). 시작 때 타이머를 0~K−1로 고르게 나눠 **엇갈려(staggered)** 재계획. 우선순위 순, 같으면 ID 순(13행) |
| 나머지 로봇 | 기존 경로(“safe fallback path”)를 유지하지만 **밀릴 수 있음**(작업 중이 아닌 한) |
| **D. 막히면** | **밀기(push)**: 우선순위 높은 로봇의 새 경로가 **낮은 로봇 1대와만** 부딪히면 그 로봇을 재귀적으로 다시 계획(EPIBT식 우선순위 상속·되돌리기, 알고리즘 2). 밀기가 실패하면 그 충돌(로봇, 시각)을 제약으로 넣고 다시 탐색. 방문 횟수 상한 M |
| 마지막 폴백 | **자기 옛 경로**(정리 1: 지도가 안 바뀌면 옛 경로는 항상 충돌 없음). 전체 재계획 아님 |
| 도달 확인 | 없음 |
| E. 엔진 | EPIBT식 재귀 밀기 + **창 시공간 A\***(W스텝, 끝점이 목표에 가까운 경로를 고름). 선택적으로 LNS로 개선(IV-D) |
| F. 보장 | 정리 1: 매 스텝 유한 시간 안에 충돌 없는 경로(지도 고정 가정). 정리 2: 교착 없음은 **TCT=0** 등 조건에서만, **T>0이면 반례 있음**(부록 A) |
| G. 평가 | 처리량(목표/스텝), 1,000스텝, 스텝당 1초 예산. 비교: PIBT, EPIBT-LNS, RHCR-PBS. warehouse-large에서 EPIBT-LNS 대비 처리량 최대 25%↑. **장애물·지연 실험 없음** |
| **H. 우리와 다른 점** | 같은 점: **작업 중 로봇을 집합으로 판단해 절대 안 움직임**(우리 C3와 효과 같음), 일부만 다시 계획, 나머지 경로 유지. 다른 점: ① 재계획 계기 = **타이머·대기**(lifelong 처리량) vs 우리 **장애물 출현**. ② 막히면 **충돌한 낮은 로봇 1대를 재귀로 밈** vs 우리 **실패한 로봇의 BFS 최단 길 위의 로봇들을 한 번에 부름**. ③ 폴백 = 옛 경로(**지도가 바뀌면 성립 안 함**) vs 우리 전체 재계획. ④ 작업 끝나면 새 목표 vs 우리 주차 후 비켜 줌. ⑤ 창(W스텝) 계획 vs 우리 끝까지 전체 경로. ⑥ 작업 시간 영향 장면(standing) 평가는 우리만 |

**→ 26.3 C3 문장을 고쳐야 한다.** "작업 중인 로봇을 움직이지 않는다"는 규칙 자체는 PUSH(2026)에 있다(lifelong 처리량 문맥).
우리가 말할 수 있는 것은 **"예기치 않은 장애물 재계획에서"** 작업 중 로봇을 고정하는 규칙과, **그 규칙이 결과를 바꾸는 장면(standing)을 평가**한 것이다.

### [P3] Lehoux-Lebacque 외 2024 — *MAPF with Real Robot Dynamics and Interdependent Tasks for Automated Warehouses* (arXiv 2408.14527, ECAI 2024 확장판, NAVER LABS)

출처: https://arxiv.org/html/2408.14527v1 (본문 전체, 부록 일부는 요약만).

| 항목 | 내용 (근거) |
|---|---|
| A. 무슨 일이 생기나 | 주문이 들어오면 **정해진 간격마다** 지금 상태에서 다시 풂(4장 도입). **예기치 않은 장애물 없음**(움직이는 장애물 = 다른 로봇뿐, 4.5). 실행 중 감시·재계획 없음(결론에서 향후 과제) |
| 세계 모델 | 실제 창고 그래프(격자 아님) → 회전·가감속을 넣은 **경로 다중 그래프**(4.3), 연속 시간(1초 단위 대기). 로봇 모양(다각형)이 겹치면 충돌(4.4) |
| 규모 | 로봇 2~10대, 실제 창고 2대 |
| **B. 작업 시간** | **있음 — 경유지(선반)마다 물건 집기/내리기 시간 d**(3장, 4.5). 고정 값(분포 아님). 알고리즘 2의 27~31행: 경유지에서 d 동안 머물 수 있어야 함 |
| 작업 중 판단 | **명시적 상태 없음** — 계획 안에 시각으로 들어 있을 뿐 |
| 작업 중 로봇을 움직이나 | **없음(재계획 자체가 없음)** |
| 작업 끝난 뒤 | 다음 경유지로, 마지막엔 대기 장소로 |
| C·D. 재계획·실패 | 실행 중 재계획 **없음**. 우선순위 계획(IPP)에서 실패하면 빈 해(알고리즘 1의 44행), **추가 로봇·폴백 없음** |
| E. 엔진 | **IPP**(동적 우선순위 순차 계획 + 예약표, 대기 장소까지 경로를 미리 예약) + **VP\***(경유지 최선 우선 탐색) |
| F. 보장 | 정리 1: 로봇마다 대기 장소가 있고 거기서 시작하면 IPP는 완전(지도·실행이 계획대로일 때) |
| G. 평가 | makespan, regret, 실행 시간, 시간 여유 Δ에 따른 고장까지 시간 |
| **H. 우리와 다른 점** | 작업 시간을 **처음 계획에** 넣은 연구(오프라인·주기적). 예기치 않은 장애물·실행 중 선택적 재계획·작업 중 로봇 고정 규칙 **없음**. "다른 로봇 경로를 예약으로 먼저 적고 계획"은 PP의 기본 구조라 우리 ①과 겹치지만, 재계획 상황의 등록 순서 문제는 다루지 않음 |

### [P4] Fejziaj 외 2026 — *On dynamic MAPF methods: review, simulations and modifications* (arXiv 2606.03735)

출처: https://arxiv.org/html/2606.03735v2 (본문 전체, 일부 표 미확인). 체계적 리뷰가 아니라 6개 방법 비교 실험 + 새 방법 A\*\*.

### [P11] Morag, Stern, Felner 2023 — *Adapting to Planning Failures in Lifelong MAPF* (SoCS 2023, pp. 47–55)

출처: 사용자가 준 PDF(01557-SoCS.MoragJ.pdf) 9쪽 전체를 직접 읽음. Get Fabric(실제 상용 창고 시스템) 설정 기반.

| 항목 | 내용 (근거) |
|---|---|
| A. 문제 | **lifelong MAPF**: 목표에 도착하면 새 목표를 받음(2장). 계획 시간이 엄격히 제한된 시스템(2.2): 제어기가 **k=3스텝마다** 계획기를 부르고, 계획기는 로봇마다 최소 k스텝 경로를 돌려줘야 함. 행동은 결정적(지연·고장 없음). **예기치 않은 장애물 없음** |
| "계획 실패"의 정의 | ① 지금 상태에 해가 없음 ② 알고리즘이 불완전해서 못 찾음 ③ 시간 한도(1초) 안에 못 찾음(1장, 2.2). 기존 연구는 실행을 멈추고 풀릴 때까지 계획했다고 지적 |
| 세계 모델 | 격자, 칸 충돌 + 맞바꾸기 충돌(2장). 엔진 RHCR + **PrP(무작위 재시작, PrPr)**, 시간 창 10, 계획 주기 3(4장) |
| 시스템(알고리즘 1) | 매 주기: 새 목표 배정 → **SelectAgents** → **Plan**(고른 로봇만, **나머지 로봇 경로는 제약으로 두고 기존 계획 유지**) → k스텝 안에 충돌·경로 없음이 남으면 **FailPolicy** → k스텝 실행 |
| **C. 누구를 다시** | **AllAgents**(전부) 또는 **Fail@LH(R)**: 앞으로 **R스텝 안에 충돌하거나 경로가 없는 로봇**만(3.3, R≥k). R=3·5가 가장 좋고 R이 크면 나빠짐(4.1) |
| 계획기(부분 해) | **Full**(실패하면 빈 해) / **Restart**(멈춘 PrP 반복의 부분 해) / **Persist**(경로를 못 찾은 로봇은 **건너뛰고** 다음 로봇 계속)(3.4). Persist가 가장 좋음 |
| **D. 실패하면 (Fail Policy, 3.5, 알고리즘 2)** | **AllStay**(모두 k스텝 정지) / **IStay**(문제 로봇만 정지, 그 때문에 새로 충돌하는 로봇도 정지 — 반복) / **IAvoid**(문제 로봇이 **한 칸만** 비켜 충돌을 피할 수 있으면 비킴, 아니면 정지). 모두 **충돌 없음 보장 + 계산 시간 무시할 수준**. 실패를 "다음 주기에 다시 계획"으로 넘김 |
| 로봇 추가·넓히기 | **없음.** 실패한 로봇을 위해 다른 로봇을 불러 함께 다시 계획하는 단계는 없음 |
| 전체 재계획 폴백 | **없음.** AllAgents는 폴백이 아니라 선택 정책의 한 가지 |
| **B. 작업 시간** | **없음.** 목표에 도착하면 **다음 계획 주기까지 그 자리에 머물고**(2.1) 새 목표를 받음. 작업 시간·작업 중 상태 없음 |
| G. 평가 | 지도 8개(empty-48-48, random-64-64-20, maze-128-128-10, room-64-64-8, warehouse 3종 등), **25~1,000대**, 스텝당 계획 1초, 200스텝, 지도마다 25개, 지표 = **처리량**(200스텝 동안 목표 도달 수). 결과: **Fail@LH(5) + Persist + IAvoid**가 가장 좋음. 예: warehouse-20-40-10-2-1 최대 처리량 AllAgents 276 vs Fail@LH(5) 450(4.1), 실패 정책 IAvoid 449 / IStay 437 / AllStay 197(표 2) |
| 저자 해석 | "AllAgents(전부 다시)는 로봇이 많고 큰 지도에서 **시간 안에 모든 경로를 찾지 못해** 나빠진다. Fail@LH는 필요한 곳에 탐색을 집중한다"(4.1). 반대로 "고르지 않은 로봇의 경로 제약이 통로를 막아 다른 로봇을 크게 돌아가게 할 수 있다"(3.3) |
| **H. 우리와 다른 점** | 같은 점: ① **문제 있는 로봇만 다시, 나머지는 경로를 제약으로 고정**(우리 Tier 0 + ①). ② **전체 재계획은 시간이 오래 걸려 오히려 나쁘다**는 근거(우리 C2·계산 중 멈춤 손해와 같은 방향, **인용하기 좋음**). ③ 계획 실패를 정면으로 다룸. 다른 점: ① 계기: 새 목표·예상 충돌(lifelong) vs 우리 **장애물 출현**. ② 실패하면 **멈추거나 한 칸 비켜서 다음 주기로 미룸**(안전 우선, 해결은 나중) vs 우리 **원인 로봇(BFS 최단 길 위)을 불러 바로 다시 계획하고, 안 되면 전체 재계획**. 장애물이 머무는 상황에서는 멈추기만 해서는 길이 안 열린다. ③ 성공률 보장 개념 없음(처리량으로 평가) vs 우리 전체 재계획 이상. ④ 우선순위: 무작위 재시작 PrP vs 우리 고정 우선순위 + 고정 먼저. ⑤ 시간 창 10스텝 vs 우리 끝까지. ⑥ 작업 시간 없음(목표에서 잠깐 머물 뿐) vs 우리 근무표·작업 중 고정 |

**우리 논문에 쓸 점**: (1) "실제 상용 창고에서도 계획 실패 처리를 그때그때(ad-hoc) 한다, 학술적으로 정리된 적이 없다"(초록·2.2) — 우리 Tier·안전망 구조의 필요성 근거.
(2) "전부 다시 계획하면 시간 한도 때문에 처리량이 떨어진다"(4.1) — 선택적 재계획의 동기.
(3) 6번 비교 기준 후보: **IStay식 폴백**(장애물에 막힌 로봇은 멈추고 다음 주기에 다시)을 우리 안전망 대신 넣어 비교할 수 있다. 단, 장애물이 머무는 우리 장면에서는 같은 문제가 반복되므로 **"전체 재계획 vs 멈추고 미루기"**의 비교가 된다(결정 필요).

## 27.3 지금까지의 판정 (2차까지 11편)

| 우리 부품·주장 | 판정 | 가장 가까운 선행 연구와 남는 차이 |
|---|---|---|
| Tier 0: 장애물과 경로가 겹치는 로봇만 | 새롭지 않음 | Park(20초 진입 창), Fejziaj 리뷰(장애물 만난 로봇 하나), FlexSIPP(늦은 로봇 하나). 우리 기준은 "칸·시각 겹침" |
| ① 고정 로봇 먼저 + 실패 원인 측정(C1) | **유지** | LNS·RS(Švancara)·IPP 모두 "나머지 고정"은 함. 그러나 **재계획에서 섞어 등록하면 숨은 충돌로 실패한다는 측정**은 없음. Park은 등록 방식 불명확 |
| ③ 길 위의 로봇 구조 | **좁혀야 함** | **LNS2 실패 기반 이웃**(출발→목적지 길 위에 앉은 로봇 + 출발 칸 지나는 로봇). 남는 차이: 시각까지 따진 BFS 최단 길, 움직이는 로봇 포함, 개수 제한 없음, 실행 중 장애물 재계획에서 한 번 넓힘 |
| Tier 1 + 안전망, 성공률 ≥ 전체 재계획(C2) | **유지** | OID(충돌 그룹 합치기, 경로가 먼저 있어야 함), PUSH(1대씩 재귀 밀기, 옛 경로 폴백 — 지도가 바뀌면 깨짐), IC-MAPF(정보 늘리기→공동→미루기), FlexSIPP(실패 시 전체 재계획 "필요"라고만), **Morag 2023(실패하면 멈추기/한 칸 비키기로 다음 주기에 미룸, 로봇 추가 없음)**. **"A\* 실패 → 길 위 로봇 → 전체 재계획"을 구조적 보장과 함께 쓴 것은 못 찾음** |
| 작업 시간 + 작업 중 고정(C3) | **좁혀야 함** | **PUSH(H0 작업 중 로봇은 밀 수 없음, lifelong)**, MCPF-D(작업 중 칸 차지, 오프라인), NAVER IPP(경유지 작업 시간, 오프라인). 반대 사례: IC-MAPF(목적지 로봇을 비키게 함), FlexSIPP(목적지 대기 = 여유). 남는 차이: **예기치 않은 장애물 재계획**에서 근무표로 작업 중 로봇을 고정하고, 작업 끝난 로봇은 주차 후 구조로 불리면 비켜 주며, **그 영향이 드러나는 장면(standing)을 평가** |
| 계산 중 멈춤 손해 지표 | 유지 | 다른 논문은 계산 시간만 잼(Park: 1초 안에 끝난 비율). 늦어진 스텝으로 바꾼 것은 못 찾음 |
