# 30. 우리 방법이 실패하는 경우 찾기 — 어떤 경우가 있고, 고칠 수 있나

> 2026-11-20, 사용자 요청: "성공률이 높다지만 100%는 아니다. 재계획에 실패하는 테스트 케이스를 찾아 어떤 경우가 있는지 알아내고,
> 해결할 수 있으면 해결하자." 이 장은 **찾기·원인 분석**까지 했고, **해결 방법은 제안만** 한다(결정 필요, 30.5).

## 30.0 세 줄 요약

1. 실패는 **좁은 통로 + 로봇 150~200대**에서만 생긴다(400개 중 0~5개). 넓은 맵, 로봇 100대 이하에서는 0이다.
2. 원인은 두 가지뿐이었다: **(가) 넓히기를 한 번만 해서 모자람**(Tier 2~3이면 풀림), **(나) PP의 우선순위 순서**(순서만 바꾸면 풀림).
   "길이 정말 끊김"이나 "시간 상한"은 한 건도 없었다.
3. 고치는 방법 두 가지를 제안한다: **Tier를 2로**, 그리고 **전체 재계획까지 실패했을 때만 순서를 바꿔 다시 시도**. 이러면 평소 속도는
   그대로이면서 "전체 재계획도 못 푸는 경우"의 대부분을 풀 수 있다(30.5).

- **(가) 넓히기가 한 번으로 모자람 — 4건.** Tier 1에서 부른 구조 로봇이 또 다른 로봇에게 막히는 경우다. 한 번 더 넓히면(Tier 2, 한 건은 Tier 3) 풀린다.
  그중 1건(#31)은 **전체 재계획도 못 푸는 경우인데 우리 방법이 Tier 3으로 푼다.**
- **(나) PP의 우선순위 순서 — 나머지 대부분.** PP는 정해진 순서대로 한 대씩 계획한다. 앞 순서 로봇이 좁은 통로를 먼저 차지해 버리면 뒤 로봇이 갈 곳이 없다.
  **순서만 바꾸면 풀린다**: 모든 케이스에서 전체 재계획을 무작위 순서로 돌리면 최소 1/60 이상 풀렸다 → **"원래 불가능한 문제"는 하나도 없었다.**
  우리 방법도 다시 계획할 로봇들의 순서만 바꾸면 18건 중 15건을 안전망 없이 푼다(그중 **완전 실패 B 8건 중 6건**).
- **원인이 아니었던 것**: 길이 정말 끊김(0건), 시간 상한(0건), 비켜 달라기 부족(0건).
- **작업 중인 로봇**: 작업 시간을 켠 케이스에서는 막힌 로봇의 길 위에 작업 중인 로봇이 서 있는 경우가 많다. 하지만 순서를 바꾸면 대부분 풀리므로
  "작업 중 로봇 때문에 절대 못 푸는" 경우는 이번 18건에는 없었다.
- **남은 3건**(standing 200대 #34, #5 두 개): 순서를 20번 바꿔도 우리 방법으로는 안 풀린다. #34는 전체 재계획이 풀어서(A) 문제없고,
  #5는 전체 재계획도 무작위 순서로 2~6/60만 풀리는 아주 빡빡한 경우다.

## 30.4 왜 "순서 바꿔 다시"를 항상 하면 안 되나 — 시간

실패하는 시도는 느리다. A\*가 갈 수 있는 곳을 다 뒤져 보고 실패하기 때문이다. 200대에서 실패하는 시도 한 번이 **0.2~0.9초**다
(전체 재계획 중앙값 0.25초보다 느림). 그리고 처음 성공하는 순서가 나올 때까지 최대 4번 실패했다. 그래서 "안전망 전에 순서를 바꿔 여러 번"
하면 이런 드문 경우에 몇 초가 걸릴 수 있다 — 빠른 재계획이라는 장점을 해친다.

## 30.5 해결 제안 (⚠ 결정 필요 — 아직 구현 안 함)

| 제안 | 무엇을 | 효과(18건 기준) | 평소 속도 | 비고 |
|---|---|---|---|---|
| **① Tier 1 → 2** | 넓히기를 한 번 더 | A 3건이 안전망 없이 풀림 | 거의 그대로(Tier 1이 실패할 때만 한 번 더) | 설정값만 바꿈 |
| **② 마지막에 순서 바꿔 다시** | **전체 재계획(안전망)까지 실패했을 때만**, 다시 계획할 로봇 순서를 바꿔 우리 방법을 최대 K번(예: 5번) 더, 그래도 안 되면 전체 재계획도 순서를 바꿔 K번 | B 8건 중 6건이 우리 방법으로 성공(남은 2건은 전체 재계획 순서 바꾸기로 일부 가능) | **그대로**(원래 실패하던 경우에만 시간을 더 씀) | 무작위 재시작은 **이미 알려진 기법**(PP with random restarts, Bennewitz 2001 — Morag 2023도 사용). 새롭다고 주장하지 않는다. 시드 고정으로 결과 재현 가능 |
| (비추천) 안전망 **전에** 순서 바꿔 다시 | | A도 대부분 안전망 없이 | 드문 경우 몇 초 | 30.4 |

**① + ②를 하면**: 평소 속도는 지금과 같고, "전체 재계획 이상" 보장은 그대로이면서 **전체 재계획이 실패하는 경우의 상당수를 우리가 푼다**
(성공률이 전체 재계획보다 **높아진다**). 다만 공정하게 하려면 비교 기준에도 "전체 재계획 + 무작위 재시작"을 같이 보고해야 한다.

**정해야 할 것**
1. ①(Tier 2)을 할까? — 추천: 한다.
2. ②(전체 재계획까지 실패했을 때만 순서 바꿔 다시)를 할까? 한다면 K는? — 추천: 한다, K=5.
3. 두 개 다 지금까지처럼 **스위치(기본 꺼짐) → 테스트 → 벤치마크로 "꺼짐 = 같음" 확인 → 켜고 전체 실험 다시**의 순서로 한다.

## 30.6 결정과 결과 (2026-11-20)

**사용자 결정**: ① **Tier 2로** (Tier 1과 시간 차이가 크지 않으면). ② 안전망 ② = **(a)만, 최대 3번** — "전체 재계획까지 실패했을 때만,
처음 영향받은 로봇 순서를 바꿔 Tier 0 → Tier 2를 다시". 전체 순서 바꾸기((b))는 넣지 않는다. 이 단계는 **안전망의 일부**로 센다.

**구현**: `ReplanConfig::order_restarts`(기본 0 = 끔), `restart_seed`(기본 0), `ReplanResult::order_restart`(몇 번째에 풀렸나).
섞기는 직접 구현(Fisher–Yates + mt19937)이라 Windows·Ubuntu에서 같은 순서. 벤치마크 `--order-restarts N --restart-seed S`, 열 `order_restart`.
확인: 꺼짐이면 기본 7개 설정 칸마다 같음, C++ 테스트 88개(안전망 ①이 성공하면 ②는 안 돎), 파이썬 스모크 [11](저장된 실제 실패 사례가 켜면 풀림).

**결과** (`tools/results/v7_restart/`, `python tools/analyze_restart.py`, 시나리오 400개, `--threads 4`):

표 읽는 법: 열은 **설정**이다. 칸 안의 **왼쪽 숫자 = 스스로 푼 수**(안전망 없이 Tier 0~1 또는 Tier 0~2에서 푼 수),
**오른쪽 숫자 = 성공한 수**(안전망까지 포함: 앞의 두 열은 안전망 ①까지, 'Tier 2 + ②3' 열은 안전망 ①과 ②까지).
'②3' = 안전망 ②에서 순서를 바꿔 다시 해 보는 횟수가 **최대 3번**(`--order-restarts 3`).
각 줄의 400개 = 넓은 맵 200개 + 좁은 통로 200개를 합친 것. **넓은 맵은 모든 설정에서 200/200 성공**이고, 실패·안전망 사용은 전부 좁은 통로에서 나왔다.

| 장면 | Tier 1(기존) 스스로 / 성공 | Tier 2 스스로 / 성공 | **Tier 2 + ②3 스스로 / 성공** | 전체 재계획 성공 |
|---|---|---|---|---|
| 기본 64×64 | 397 / 399 | 398 / 399 | **398 / 400** | 393 |
| 작업 시간 64×64 | 396 / 399 | 398 / 399 | **398 / 400** | 393 |
| standing 64×64 | 395 / 398 | 395 / 398 | **395 / 399** | 386 |
| standing + 작업 시간 64×64 | 395 / 397 | 395 / 397 | **395 / 399** | 388 |
| standing 32×32 | 399 / 399 | 399 / 399 | **399 / 400** | 392 |

- **Tier 2 시간**: Tier 1이 실패한 드문 경우(400개 중 1~2개)에만 달라진다. 중앙값은 같고, 느린 쪽은 Tier 2가 전체 재계획 대신 풀어서
  오히려 줄었다(같은 조건 비교에서 p95·최대가 Tier 2 쪽이 같거나 낮음). → **Tier 2 채택.**
- **안전망 ②**: 설정마다 1~2개를 더 푼다. 우리 방법의 성공률은 전체 재계획보다 6~13개 높다(Tier가 전체 재계획이 못 푸는 경우를 풀고, ②가 더 푼다).
- 남은 실패: standing 64×64의 #5류(순서를 바꿔도 거의 안 풀리는 아주 빡빡한 경우) 1~2개.
- ⚠ 시간은 동시 실행 값이라 9번에서 `--threads 1`로 다시 잰다.

**우리 방법 설정(이제부터)**: `--order fixed-first --reachability --rescue path --tiers 2 --order-restarts 3`

### 30.7 시간 확인 — 한 번에 하나씩 잰 정확한 값 (2026-11-20, `tools/results/v7_timing/`)

예전 설정(①②③ + Tier 1)과 지금 설정(①②③ + Tier 2 + 안전망 ② 3번)을 **같은 시나리오**로 `--threads 1`에서 비교. 우리 방법 계산 시간(ms).

| 지도 | 로봇 | 우리 방법 중앙값 예전 → 지금 (ms) | 우리 방법 최대 예전 → 지금 (ms) | 전체 재계획 중앙값 (ms) | 결과가 달라진 시나리오 |
|---|---|---|---|---|---|
| 64×64 넓은 맵 | 200대 | 12.6 → 11.5 | 100 → 100 | 453 | 0 |
| 64×64 좁은 통로 | 150대 | 9.8 → 9.9 | 253 → 276 | 125 | 1 (Tier 2로 풀림, 42 → 17 ms) |
| 64×64 좁은 통로 | 200대 | 17.0 → 16.9 | 785 → 824 | 147 | 1 (실패 → 안전망 ②로 성공, 624 → 637 ms) |
| 128×128 넓은 맵 | 300 / 500대 | 54 → 52 / 91 → 88 | 1532 → 1530 / 633 → 659 | 6,415 / 4,357 | 0 |
| 128×128 좁은 통로 | 300 / 500대 | 55 → 52 / 132 → 143 | 125 → 122 / 604 → 715 | 3,327 / 4,033 | 0 |

(128×128은 지도·로봇 수마다 10개. 64×64는 50개. 단위 ms — 예: 6,415 ms = 6.4초. 128×128은 표본이 10개라 흔들림이 크다
(넓은 맵 300대가 500대보다 오래 걸린 것도 그 때문). 40개로 잰 값은 25장: 전체 재계획 300대 6.6초, 500대 17.4초.
이 실험에서도 모든 시나리오가 성공했다(넓은 맵·좁은 통로 모두).)

**같은 실험의 성공 수.** 우리 방법 칸은 "**우리가 스스로 푼 수 / 우리가 성공한 수**"(성공 = 스스로 + 안전망으로 푼 것). 마지막 열은 **전체 재계획만 따로 돌렸을 때** 성공한 수다.

| 지도 | 로봇 | 시나리오 | 우리 예전(Tier 1): 스스로 / 성공 | **우리 지금(Tier 2 + ②3): 스스로 / 성공** | 전체 재계획만: 성공 |
|---|---|---|---|---|---|
| 64×64 넓은 맵 | 50 / 100 / 150 / 200대 | 50씩 | 50/50 전부 | **50/50 전부** | 50 전부 |
| 64×64 좁은 통로 | 50 / 100대 | 50씩 | 50/50 | **50/50** | 49 / 49 |
| 64×64 좁은 통로 | 150대 | 50 | 49/50 | **50/50** | 49 |
| 64×64 좁은 통로 | 200대 | 50 | 48/49 | **48/50** | 46 |
| 128×128 넓은 맵 | 300 / 500대 | 10씩 | 10/10 | **10/10** | 10 |
| 128×128 좁은 통로 | 300 / 500대 | 10씩 | 10/10 | **10/10** | 10 |

- 128×128은 이번 실험에서 **전부 성공, 전부 안전망 없이** 풀었다. 다만 칸마다 10개라 표본이 작다. 40개로 잰 25장 결과(우리 예전 설정)도
  80개 중 80개 성공, 79개를 안전망 없이 풀었다(좁은 통로 500대 1개만 안전망 ①).
- 좁은 통로 64×64 200대: 전체 재계획만 돌리면 4개 실패(46). 그중 3개는 우리 Tier가 영향받은 로봇만 다시 계획해서 풀었고(나머지 경로를 그대로 두니 풀림),
  남은 1개는 예전 설정에서 실패(49) → 지금은 안전망 ②가 풀어 50/50. 우리 안전망 ①도 전체 재계획이지만, Tier가 먼저 풀어서 **전체 재계획보다 성공률이 높다.**

- **시간 문제 없음.** Tier 2와 안전망 ②는 앞 단계가 실패한 드문 경우에만 돌아서, 나머지 시나리오는 계산이 똑같다. 차이는 측정 흔들림 수준.
- 안전망 ②가 실제로 돈 경우(실패하던 시나리오)도 시간이 13 ms만 늘었다.
