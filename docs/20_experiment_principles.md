# 20. 논문 실험 설계 원칙

> 2026-11-17 작성. 일정 5번(실험 준비)부터 9번(비교 실험)까지, 벤치마크·그래프·표를 만들 때 이 문서를 기준으로 삼는다.
> 5번에서 벤치마크에 넣는 옵션과 열은 이 원칙에 맞춰 정했다([21장](21_experiment_prep_design.md)).

## 20.0 왜 이 문서가 필요한가 — 한 줄 요약

18장 2-1단계에서 **A\*의 "동점이면 아무거나"라는 작은 규칙 하나가 "덜 건드림" 우위를 약 23배에서 약 2배로 바꿔 놓았다.**
즉, 우리가 잰 숫자는 "방법의 차이"뿐 아니라 "밑에 깔린 엔진의 우연한 성질"에도 크게 흔들린다.
이 문서는 그런 일이 논문에서 다시 생기지 않도록, **무엇을 고정하고, 무엇을 바꾸며, 무엇을 재는지**를 미리 정해 둔다.

비유로 말하면: 두 요리사의 실력을 비교하려면 **같은 재료·같은 불·같은 냄비**를 줘야 한다(엔진 고정).
그리고 "요리사가 바뀐 것"만으로 맛이 달라졌다는 걸 보이려면, 재료 하나씩만 바꿔 봐야 한다(ablation).
마지막으로 "맛"을 잴 때, 손님 기분에 따라 오락가락하는 점수는 쓰지 않는다(우연에 약한 지표 버리기).

## 20.1 원칙 1 — 엔진은 고정하고, 논문에 적는다

"엔진" = 재계획 방법이 공통으로 쓰는 밑바닥 부품. 모든 방법(전체 재계획, 우리 방법, 비교 기준)이 **같은 엔진**을 쓴다.

| 엔진 부품 | 지금 값 | 논문에 적을 문장(초안) |
|---|---|---|
| 한 로봇의 길찾기 | 시공간 A\*, 4방향 + 제자리 대기, 한 스텝에 한 칸 | "space-time A\* with wait action" |
| 휴리스틱 | 맨해튼 거리 | |
| **동점 규칙** | f가 작은 쪽 → g가 큰 쪽 → 먼저 넣은 쪽(18장 2-1) | "ties broken by larger g, then FIFO" |
| 장부 | 칸 점유 + 자리 맞바꾸기 금지 + 도착 후 영원히 머묾(꼬리 예약) | |
| 굳는 시각 최적화 | 장부가 굳은 뒤 같은 칸 한 번만 확인(18장 2-2) — **결과는 안 바뀌고 시간만 줄어듦** | 시간 비교 때 모든 방법에 똑같이 켬 |
| 시간 상한 | `max_timestep = 256` | |
| 작업 시간 규칙 | 작업 중엔 절대 안 움직임, 끝나면 주차(비켜 줄 수 있음)(17장) | 비교 기준도 같은 규칙을 지킨다 |

**지킬 것**
- 결과 표마다 **git 커밋 해시**(또는 태그)를 함께 기록한다. 결과 폴더 이름에 버전을 넣는다(예: `tools/results/v2_tiebreak/`).
- 엔진을 바꾸면(예: 휴리스틱 개선) **모든 방법을 다시 잰다.** 한 방법만 새 엔진으로 재고 옛 숫자와 비교하지 않는다.
- 비교 기준(Park 2026식, LNS2식, 일정 6번)도 이 엔진 위에 구현한다. "그 논문의 원래 구현"이 아니라 "그 논문의 **선택 규칙**을
  같은 엔진에 얹은 것"임을 논문에 명시한다.

## 20.2 원칙 2 — "에이전트 축" ablation 표

우리 방법은 **"어떤 로봇을, 어떤 순서로 다시 계획하나"**(에이전트 축)만 바꾼다. 길찾기 엔진은 그대로다.
그래서 효과를 보일 때도 에이전트 축의 부품을 **하나씩 빼 보는** 표를 만든다.

우리 방법의 부품:

| 부품 | 스위치 | 하는 일 |
|---|---|---|
| ① 고정 먼저 | `--order fixed-first` | 안 다시 계획하는 로봇을 장부에 먼저 적고, 그 위에 영향받은 로봇을 얹는다(12장) |
| ② 도달 확인 | `--reachability` | 로봇이 아무도 없어도 못 가는 경우를 바로 실패 처리(13장) |
| ③ 경로 구조 선택 | `--rescue path` | 구조 로봇을 "막힌 칸"이 아니라 "가장 짧은 길 위"에서 고른다(13장) |
| (+) 양보 요청 | `--yield` | 기본 끔. 효과 작아서 한 줄로만(19장) |

ablation 표의 모양(일정 9번에서 채움):

| 줄 | ① | ② | ③ | 성공률 | 안전망 없이 성공 | 다시 계획한 로봇 수 | 목적지 밖 시간 | 늦어진 로봇 수 | 시간(중앙값/p95/최대) |
|---|---|---|---|---|---|---|---|---|---|
| 전체 재계획(기준) | — | — | — | | | | | | |
| 우리 방법 | ✔ | ✔ | ✔ | | | | | | |
| − ① 고정 먼저 | ✘ | ✔ | ✔ | | | | | | |
| − ② 도달 확인 | ✔ | ✘ | ✔ | | | | | | |
| − ③ 경로 구조 | ✔ | ✔ | ✘ | | | | | | |
| + 양보 요청 | ✔ | ✔ | ✔ | | | | | | |
| Park 2026식 / LNS2식 | (일정 6번) | | | | | | | | |

- "원래 방식"(`--order priority --rescue blocked`, ①②③ 전부 끔)은 **논문에 넣지 않는다**(2026-09-14 결정). 내부 확인용으로만 쓴다.
- 작업 시간 수준(21장에서 정함)마다 이 표를 하나씩 만든다. 작업 시간이 길어질수록 "작업 중이라 못 비키는 로봇"이 늘어나므로,
  어떤 부품의 효과가 작업 시간에 따라 커지는지 줄어드는지가 논문의 관찰 거리다.

## 20.3 원칙 3 — 동점 규칙 민감도 실험

18장에서 본 것처럼, **동점 규칙만 바꿔도 숫자가 크게 바뀔 수 있다.** 그래서 논문의 결론이 "우리가 고른 동점 규칙 덕분"이
아니라는 것을 보여야 한다.

방법: 동점 규칙을 몇 가지로 바꿔서 ablation 표의 핵심 줄(전체 재계획, 우리 방법)을 다시 잰다.

| 규칙 이름 | 동점일 때 | 성질 |
|---|---|---|
| 기본(지금) | g 큰 쪽 → 먼저 넣은 쪽 | 결정적(같은 입력 → 같은 결과) |
| g 작은 쪽 | g 작은 쪽 → 먼저 넣은 쪽 | 결정적, 다른 쪽으로 치우침 |
| 무작위(씨앗 k개) | g 큰 쪽 → 무작위 | 씨앗마다 결정적. 예전 "아무거나"와 비슷한 흔들림을 일부러 만든다 |

**결론이 튼튼하다는 기준**: 규칙을 바꿔도 "어느 방법이 더 나은가"의 **순서**가 바뀌지 않으면 된다. 숫자 크기는 달라도 된다.

이 실험에는 `AStarConfig`에 동점 규칙 스위치가 필요하다. 넣는 시점은 21장 21.6에서 정한다.

## 20.4 원칙 4 — 무엇을 재나(지표)

### 버리거나 낮추는 지표: "바뀐 로봇 수"

"재계획 전후로 움직임이 달라진 로봇 수"(`*_changed`)는 **우연에 약하다.** 다시 계획한 로봇이 길이만 같은 다른 길을 고르면
"바뀜"으로 잡히는데, 그건 동점 규칙이 정한다(18장 2-1에서 전체 재계획 75.5 → 7.7). 그래서 **본문 지표에서 뺀다.**
부록에 "참고, 동점 규칙에 민감함" 표시와 함께만 둔다.

### 본문 지표

| 지표 | 벤치마크 열 | 무엇을 말해 주나 | 우연에 강한 이유 |
|---|---|---|---|
| 성공률 | `*_ok` | 길을 찾았나 | |
| 안전망 없이 성공 | `escalation_tier >= 0` | 선택적으로만 풀었나 | |
| **다시 계획한 로봇 수** | `selective_replanned` (전체 재계획은 정의상 전부) | 얼마나 넓게 손댔나 | 길을 어떻게 골랐든 "손을 댔는지"만 센다 |
| **목적지 밖 시간 합** | `*_away` | 로봇들이 목적지에 못 있고 돌아다니는 시간의 합. 작업 시간·주차를 넣은 모델에 맞는 비용 | 길이가 같은 다른 길을 골라도 값이 같다 |
| **늦어진 로봇 수** | `*_delayed` (21장에서 추가) | 원래 계획보다 목적지에 늦게 (다시) 도착한 로봇 수. "현장에서 체감하는 피해" | 길이가 같은 다른 길이면 늦어지지 않는다 |
| 경로 비용 합(SOC) | `*_soc` | MAPF 표준 지표. 다른 논문과 비교용 | |
| 재계획 시간 | `*_ms` | **평균 대신 중앙값·p95·최대** | 몇 개의 느린 실패가 평균을 크게 흔든다(18장) |

### 시나리오를 설명하는 열(결과가 아니라 "어떤 상황이었나")

| 열 | 뜻 |
|---|---|
| `current_time` | 장애물이 나타난 시각 |
| `working_at_t` | 그 시각에 작업 중이던 로봇 수 — 작업 시간 실험이 "정말로 작업 중인 로봇이 있는 상황"을 만들었는지 확인 |

## 20.5 원칙 5 — 시나리오는 짝지어 비교한다

- **같은 씨앗 = 같은 시나리오.** 모든 방법이 같은 (로봇 배치, 장애물, 시각)을 받는다(지금도 그렇다).
- 작업 시간을 켜고 끌 때도 **로봇 배치와 장애물은 그대로** 두고 작업 시간만 바뀌게 한다(21장 21.2 "따로 뽑는 난수").
  그래야 "작업 시간 때문에 생긴 차이"만 본다.
- 두 방법의 차이는 **같은 시나리오끼리의 차이**로 계산한다(짝지은 비교). 통계 검정은 짝지은 Wilcoxon 부호 순위 검정,
  신뢰구간은 짝지은 차이의 부트스트랩을 쓴다(일정 9번).
- 시나리오는 "처음 계획이 성공하고, 장애물이 실제로 누군가를 막는" 것만 쓴다(지금 벤치마크 규칙). 논문에 이 거르기 규칙과
  거른 비율(`plan_attempts`)을 적는다.

## 20.7 2026-11-18 추가 원칙 (23장 실험에서)

- **시간은 `--threads 1`(한 번에 하나씩)로 잰다.** 모든 코어로 동시에 돌리면 계산끼리 방해해서 시간이 약 2.5배 부풀려졌다(배수는 유지).
  결과 열은 스레드 수와 상관없이 같으므로, 성공률·품질은 여러 코어로, 시간 표는 한 번에 하나씩 돌린 결과로 만든다.
- **계산 시간을 손해로 넣은 "총 늦어짐"을 본문 지표에 넣는다.** 규칙: 한 스텝 = Δ초, 계산 c초 동안 모든 로봇 정지(k = max(0, ⌈c/Δ⌉ - 1) 스텝).
  Δ = 0.25 / 0.5 / 1 / 2초를 함께 보고, "차이가 나는 조건"(빠른 로봇, 많은 로봇)과 "안 나는 조건"을 둘 다 적는다.
- **본 실험의 장면은 두 가지**: 기존 장면(`--obstacle-mode path`)과 **standing 장면**(돌아가는 길목에 서 있는 로봇, `--obstacle-mode standing`).
  작업 시간 수준(0 / U[1,10] / U[30,60])은 두 장면 모두에서 돌린다.
- **규모**: 32×32, 64×64, 128×128(로봇 300·500대, 시간 상한 512). 1,000대는 처음 계획부터 자주 실패하고 전체 재계획이 너무 느려 뺐다.
