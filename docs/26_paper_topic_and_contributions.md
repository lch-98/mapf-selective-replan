## 26.0 한 문장 주제 (초안)

> **물류 창고에서 로봇들이 움직이는 도중 예기치 않은 장애물이 나타났을 때, 로봇을 멈춰 세우지 않고 빠르게 경로를 고치는
> PP 기반 선택적 재계획 — 성공률은 전체 재계획보다 낮아지지 않고, 작업 중인 로봇은 건드리지 않는다.**

영문 제목 후보:
- *Fast and Safe Selective Repair for Prioritized Multi-Agent Path Finding under Unexpected Obstacles in Warehouses*
- *Selective Replanning for Online Obstacle Recovery in Warehouse MAPF with Service Times*

## 26.1 "처음 계획(plan)이 아니라 실행 중 재계획(replan)을 타겟으로" — 동의한다

**좋은 점**

1. **우리 코드가 이미 그렇다.** 처음 계획은 평범한 PP다. 처음 계획이 실패하는 배치는 버리고 쓰지 않는다(아래 26.5).
   우리가 손댄 것은 전부 `replan()` 안에 있다. 그러니 주제를 replan으로 잡는 게 정직하다.
2. **경쟁 상대가 줄어든다.** 처음 계획의 품질 경쟁(CBS, PBS, LNS, LaCAM 등 수천 대를 몇 초에 푸는 연구)과 겨루지 않아도 된다.
   우리 질문은 "처음 계획이 이미 있을 때, 장애물이 나타나면 얼마나 빨리, 얼마나 안전하게 고치나"다.
3. **현장 질문과 맞는다.** 물류 현장에서 아픈 순간은 처음 배정 때보다, 운영 중 막혔을 때 모두가 멈추는 순간이다.

**보완할 점 3가지** — 이것 없이 "replan을 고려했다"만 말하면 차별점이 되지 않는다.

1. **"실행 중 재계획을 했다" 자체는 새롭지 않다.** Park 2026, PIEF, FlexSIPP, IC/WinC-MAPF도 실행 중에 다시 계획한다(24.2).
   그래서 차별점은 **"replan을 한다"가 아니라 "어떻게 하길래 무엇이 보장되고 얼마나 빠른가"**에 둬야 한다(26.3).
2. **"끊김 없는(seamless)"은 말이 아니라 숫자로 보여 줘야 한다.** 우리는 이미 그 지표가 있다. 계산하는 동안 모든 로봇이 멈춘다고 두고
   로봇당 늦어진 스텝을 센다(23장, 그림 B). 128×128 500대에서 한 칸 2초짜리 느린 로봇도 **9.2 → 0.2스텝**이다.
   논문에서는 "끊김 없음 = 재계획 계산 동안 멈춘 시간이 거의 0"으로 정의해서 쓴다.
3. **"물류 현장"은 조건으로 구체화한다.** 실제 창고 로그는 없다. 그래서 "물류 현장을 흉내 낸 조건"이라고 쓰고, 조건을 적어 둔다:
   좁은 통로 지도, 수백 대, 도착 후 작업 시간(작업 중 로봇은 못 움직임), 나타나서 머무는 장애물.

## 26.2 섞어 만든 것임을 밝힌다 — 부품별 출처

논문에서 "새 방법"이라고 하면 안 되는 부분은 처음부터 출처를 밝힌다. 그래야 심사에서 "이건 X 논문에 있다"는 지적을 피한다.

| 우리 부품 | 어디서 온 발상인가 | 논문에서 쓰는 말투 |
|---|---|---|
| PP + 시공간 A\* (엔진) | Silver 2005(협력 경로 탐색), Erdmann & Lozano-Pérez 1987(우선순위 계획) | "we use standard PP with space-time A\*" |
| Tier 0: 영향받은 로봇만 다시 | Park 2026, PIEF(Švancara 2019) | "following [Park, PIEF], we first replan only affected agents" |
| ① 고정 로봇 먼저 적기 | MAPF-LNS / LNS2(Li 2021·2022)의 "나머지 경로 고정" | "as in LNS, non-replanned paths are fixed first" |
| Tier 1: 넓혀 가기 | PIEF(부딪히면 추가), IC/WinC-MAPF(단계적 확장) | "escalation in the spirit of [PIEF, WinC-MAPF]" |
| ③ 길 위의 로봇만 구조 | LNS2의 충돌 기반 이웃 선택과 비슷한 발상 | "similar to conflict-based neighborhoods in LNS2, but…" |
| ② 도달 확인(BFS) | 흔한 사전 검사 | 기여로 주장하지 않음 |
| 작업 시간 | MCPF·스케줄 제약 MAPF(오프라인 계획) | "service times are studied in offline MAPF [Zhang 2023]; we bring them to online repair" |
| 안전망(전체 재계획) | 일반적 | 기여로 주장하지 않음 — 다만 26.3의 보장을 만드는 부품 |

> ⚠ 출처 연도·저자는 6′(문헌 조사)에서 원문으로 다시 확인한다. 위 표는 24장의 짧은 검색 기준이다.

## 26.3 그래서 우리 것은 무엇인가 — 차별점 3개 (강한 순서)

부품 하나하나는 빌려 왔지만, **아래 3개는 기존 연구에서 찾지 못한 것**이고 데이터가 있다.

### C1. "PP 선택적 재계획이 왜 실패하는가"를 측정해서 밝히고, 고쳤다

- 발견: 영향받은 로봇만 다시 계획할 때 실패의 **99%는 "적는 순서"** 때문이다. 다시 계획하는 로봇이 우선순위가 높으면,
  안 움직이는 로봇의 길을 모른 채 계획하고, 나중에 숨은 충돌이 터진다(11·12장).
- 고친 것: 안 움직이는 로봇 길을 먼저 적는다(①). 안전망 없이 스스로 푼 수가 **243 → 394 / 400**(①만), ③까지 켜면 **397 / 400**(64×64, 400 시나리오).
- 왜 차별점인가: "나머지 고정" 기법은 LNS와 같다. 그러나 **실행 중 PP 재계획에서 이게 실패의 주원인이라는 측정**은 찾지 못했다.
  Park 2026은 실패를 보고하지 않는다(성공률 100%로 보고). → **6번에서 Park식이 우리 엔진에서 얼마나 실패하는지가 C1의 핵심 증거**다.

### C2. 성공률은 전체 재계획보다 절대 낮지 않으면서, 수십~백 배 빠르다

- 구조: Tier 0 → Tier 1(A\*가 경로를 아예 못 찾아도, 실패한 로봇의 "로봇 없을 때 가장 짧은 길" 위의 로봇만 불러 넓힘) → 안전망.
- 보장: 안전망이 전체 재계획이므로 성공률은 구조적으로 전체 재계획 이상이다. 데이터에서도 반례 0 / 9,200.
- 그런데 안전망을 거의 안 쓴다. **99% 이상을 스스로 푼다**(그림 0, 128×128에서도 79/80).
- 속도: 64×64 **8~21배**, 128×128 **107~137배**(한 번에 하나씩 잰 중앙값). 계산 동안 멈춤까지 넣으면 로봇당 늦어짐 9.2 → 0.2(500대, 한 칸 2초).
- PIEF와의 차이: PIEF는 경로가 나온 뒤 충돌만 검사하므로 **경로가 아예 안 나오는 실패**를 못 다룬다. 우리 Tier 1은 그걸 다룬다.

### C3. 작업 중인 로봇은 움직이지 않는다는 규칙을 실행 중 재계획에 넣었다

- 작업 시간 자체는 오프라인 계획 연구에 있다. **실행 중 장애물 재계획 + 작업 시간을 함께 다룬 연구는 짧은 검색에서 찾지 못했다**(24.2).
- 이 규칙이 결과를 바꾸는 장면(우회로에 서 있는 로봇, standing)에서, 전체 재계획은 최대 37% 시나리오에서 결과가 바뀌고,
  우리 방법은 4~5%만 바뀐다(23장, 그림 C). 작업 시간을 0으로 두면 이런 장면에서 **실제로는 실행할 수 없는 계획**이 나온다.
- 주의: "작업 시간을 처음 고려했다"가 아니라 **"실행 중 선택적 재계획에서"**라는 조합으로 말한다.

### 차별점이 아닌 것 (쓰지 말 것)

- "영향받은 로봇만 다시 계획하는 새 방법" — Park, PIEF에 있다.
- "다른 로봇을 고정하는 새 방법" — LNS에 있다.
- "기존 연구는 물류 현장을 고려하지 않았다" — 사실이 아니다(RHCR, MAPD는 창고를 다룬다).
- 도달 확인(BFS), BFS 메모장 — 속도 장치일 뿐이다.

## 26.4 6번(비교 기준)은 이 차별점을 증명하는 실험이어야 한다

| 비교 기준 | 증명하려는 차별점 | 기대 / 위험 |
|---|---|---|
| 전체 재계획 | C2(속도, 성공률 이상) | 이미 있음 |
| **Park 2026식**(장애물 구간에 곧 들어갈 로봇만, 실패 시 안전망) | **C1** — 원래 순서(우선순위)로 적으면 자주 실패하는가 | 자주 실패하면 C1이 강해진다. 거의 안 실패하면 C1은 약해지고 기여는 C2·C3 쪽으로 좁아진다 |
| **LNS2식 수리**(충돌 기반 이웃을 골라 반복) | C2 — 같은 "일부만 다시" 계열과 시간·성공률 | 반복이 많으면 느리고, 적으면 실패. 우리가 둘 다 나은지 확인 |
| (선택) PIEF식(경로가 나온 뒤 부딪히는 로봇만 추가) | C2의 "A\* 실패도 다룸" | 경로가 안 나오는 장면에서 PIEF식은 바로 안전망으로 간다 → 그 비율을 보여 줌 |

모든 비교 기준은 **같은 엔진·같은 시나리오·같은 안전망**을 쓴다(24.3). 그래야 "선택 규칙"의 차이만 비교된다.

## 26.5 범위를 명확히 하는 문장 (논문 "실험 설정"에 들어갈 것)

- 처음 계획은 표준 PP로 만든다. **처음 계획이 실패한 배치는 버리고 다시 뽑는다.** 이 비율을 보고한다(아래, 이유별로 따로 셈).
- 장애물이 아무도 막지 않는 배치도 버린다(재계획이 필요 없으므로). 이건 "처음 계획 실패"와 다른 이유라서 따로 센다.
- 따라서 결과는 "처음 계획이 가능한 배치에서, 장애물이 실제로 길을 막았을 때"의 재계획 성능이다.

(버린 비율 표는 측정 후 채움 — 26.6)

## 26.6 버린 비율 — 이유별 (2026-11-19 측정)

벤치마크에 열 두 개를 추가했다(맨 끝 열, 기존 열·결과 불변).

- `plan_failures`: **처음 PP 계획이 실패**해서 버린 배치 수
- `obstacle_retries`: 계획은 됐지만 **장애물이 아무도 안 막아서**(standing 장면: 조건에 맞는 서 있는 로봇이 없어서) 버린 배치 수
- 항상 `plan_attempts = plan_failures + obstacle_retries + 1`(1 = 실제로 쓴 배치). 모든 행에서 확인(위반 0).

**버린 비율 = 해당 이유로 버린 수 ÷ 뽑아 본 배치 수.** 자료: `tools/results/v5_discard/`, 계산: `python tools/analyze_discard.py tools/results/v5_discard/*.csv`

### 처음 PP 계획 실패로 버린 비율 (기존 장면, 그림 0의 실험)

| 지도 | 로봇 수 | 넓은 맵(open) | 좁은 통로 맵(corridor) |
|---|---|---|---|
| 32×32 | 5 / 10 / 20 / 40 | 0 / 0 / 0 / 0% | 0 / 0 / 3.8 / **10.7%** |
| 64×64 | 50 / 100 / 150 / 200 | 0 / 0 / 0 / 0% | 2.0 / 12.3 / **39.0** / **76.5%** |
| 128×128 | 300 / 500 | 0 / 0% | **23.1** / **79.6%** |

- 기존 장면에서는 **버린 이유가 전부 "처음 계획 실패"**다. "장애물이 아무도 안 막음"은 0번이다(장애물을 길 중간에서 고르므로).
- **넓은 맵에서는 한 번도 안 버렸다.** 버림은 전부 좁은 통로 맵에서, 로봇이 많을 때 생긴다.
- 64×64 통로 200대: 뽑은 213개 중 163개가 처음 계획부터 실패. 한 시나리오는 17번 실패 후 18번째에 얻었다.
- 128×128 통로 500대: 뽑은 98개 중 78개 실패(79.6%).
- 예전 25장의 "62%, 66%"는 넓은 맵과 통로 맵을 합친 값이라 작게 보였다. 통로 맵만 보면 76.5%, 79.6%다.

### standing 장면 (작업 시간 실험, 그림 C)

| 지도 | 로봇 수 | 처음 계획 실패 | 서 있는 로봇이 없어서 버림 |
|---|---|---|---|
| 32×32 통로 | 5 / 10 / 20 / 40 | 0 / 0 / 3.8 / 10.7% | 51.0 / 7.4 / 0 / 0% |
| 32×32 넓은 맵 | 5 / 10 / 20 / 40 | 0 / 0 / 0 / 0% | 79.7 / 45.7 / 0 / 0% |
| 64×64 | (기존 장면과 같음) | 위 표와 같음 | 0% |

- 예전에 standing 32×32 5대에서 "71% 버림"으로 보였던 것은 **처음 계획 실패가 아니라 서 있는 로봇을 못 찾아서**였다. 로봇이 5~10대뿐이면
  "우회로에 이미 도착해 서 있는 로봇"이 있는 배치가 드물다.

### 쉬운 해석과 논문에 쓸 문장

- 우리 실험은 **"처음 PP 계획이 가능한 배치"만** 쓴다. 좁은 통로에 로봇이 많으면 그런 배치는 소수(20~25%)다.
  이건 **처음 계획(plan)의 한계**이고, 우리 주제(replan)의 바깥이다(26.1). 하지만 숨기지 말고 적는다.
- 문장 예: *"Initial plans are generated by standard PP; instances where PP fails to find an initial plan are resampled
  (up to 79.6% of samples in the densest corridor setting, 0% on open maps). All reported results are conditioned on
  instances with a feasible initial plan and an obstacle that blocks at least one planned path."*
- 생각해 볼 점(결정 아님): 이 조건 때문에 통로 200·500대 결과는 "PP가 풀 수 있는 쉬운 쪽 배치"에 치우쳐 있을 수 있다.
  처음 계획을 더 강한 방법(예: PBS, LaCAM)으로 만들면 이 치우침이 줄지만, 엔진이 달라진다. 지금은 조건을 적는 것으로 둔다.
