## 28.1 Park식을 어떻게 옮겼나

Park 외 2026(27장 P1)의 규칙을 우리 격자·이산 시간으로 옮겼다.

| Park 논문 | 우리 엔진에서 | 근거 |
|---|---|---|
| 장애물이 있는 구간에 **지금부터 20초 안에** 들어갈 로봇만 다시 계획 | 장애물 칸에 **지금부터 W스텝 안에** 닿는 로봇만 지금 다시 계획. **W = 20초 ÷ 한 칸 시간**: 한 칸 2초(TurtleBot) → W=10, 1초(창고) → W=20, 0.5초(빠름) → W=40 | 3.4절 |
| 20초 뒤에 들어갈 로봇은 지금은 안 건드림 | **미룬 로봇**: 옛 경로를 그대로 두고, 장부에는 장애물에 닿기 바로 전 시각까지만 적는다(그 뒤는 아직 안 정해졌으므로). 창에 들어오는 시각(닿는 시각 − W)에 다시 계획한다 | 3.4절, 실제 시스템은 로봇이 다가올 때 다시 감지 |
| 영향 없는 로봇은 경로 유지 | 같음. 등록 순서는 논문에 없으므로 **두 가지 다**: 섞어 등록(원래 우선순위 순) / 고정 먼저(①) | 3.4절(불명확) |
| 실패 처리 없음 | 로봇 추가 없음(`--tiers 0`). 실패하면 **바로 안전망(전체 재계획)** — 공정하게 같은 안전망 | 논문에 없음 |
| CBS 엔진, 구간 그래프 | 우리 PP + 시공간 A\*(엔진 고정 원칙) | 20장 원칙 1 |

### 28.1.1 Park 논문과 조건이 같은 것 / 다른 것 (2026-11-19 사용자 질문으로 정리)

**작업 시간**: 이번 Park식 실험은 **모든 방법(우리 방법·원래 방식·Park식·전체 재계획)을 작업 시간 0으로** 돌렸다(`--service` 없음,
모든 결과 파일에서 `working_at_t` 합 = 0으로 확인). Park 논문에도 작업 시간이 없으므로 이 점은 맞췄다.
작업 시간을 켠 비교(standing 장면 포함)는 아직 안 했다 — 우리 C3 쪽 비교라 따로 돌린다(아래 "남은 것").

| 조건 | Park 논문 | 이번 Park식 실험 | 같은가 |
|---|---|---|---|
| 작업 시간 | 없음 | 0(모든 방법) | **같음** |
| 목적지 도착 후 | 작업을 마치면 **새 작업을 온라인으로 받아 계속 움직임**(lifelong, 30분 운행) | 새 작업 없음. **목적지에 계속 머묾**(꼬리 예약). 머무는 로봇은 "주차 중"이라 전체 재계획(안전망)에서는 다시 계획될 수 있지만, Park식 Tier 0에서는 안 건드림 | **다름** — 우리 벤치마크는 장애물 한 번 + 재계획 한 번(일회성)이라 모든 방법이 같은 조건 |
| 장애물 | 고정 + **움직이는** 장애물, 감지 반경 10 m | 나타나 머무는 고정 장애물 1~3칸만 | 부분적으로 같음 |
| 누구를 다시 | 장애물 구간에 20초 안에 들어갈 로봇 | 장애물 칸에 W스텝 안에 닿는 로봇(W = 20초 ÷ 한 칸 시간) | 옮김(구간 → 칸) |
| 엔진 | CBS(구간 그래프, 연속 시간) + Safe Interval·통행 여유 Δ(s) | 우리 PP + 시공간 A\*(격자). Safe Interval·Δ(s) **없음** | **다름**(엔진 고정 원칙으로 일부러) |
| 나머지 로봇 등록 순서 | 논문에 없음 | 섞어 / 고정 먼저 둘 다 | 논문이 불명확해서 둘 다 |
| 실패하면 | 논문에 없음(성공률 100% 보고) | 바로 안전망(전체 재계획) | 우리가 정함 |
| 시행 | 한 번에 30분 운행, 20회 | 시나리오 400개(장애물 한 번씩) | 다름 |

**그래서 이 비교가 말할 수 있는 것**: "Park의 **로봇 고르는 규칙**(시간 창)을 우리 엔진·우리 장면에 넣었을 때"의 결과다. Park 논문의 방법 전체(CBS + 구간
지침 + Safe Interval)를 재현한 것은 아니다. 논문에는 "Park 외(2026)의 선택 규칙을 같은 PP 엔진에 구현한 것(Park-style selection)"이라고 쓴다.

### 28.1.2 리뷰어 지적("똑같이 재현한 게 아니다")에 대비하는 법

1. **이름과 주장 범위**: "Park 외(2026)의 방법"이 아니라 **"Park식 선택 규칙(Park-style selection)을 같은 PP 엔진에 구현"**이라고 쓴다.
   주장은 "Park 방법보다 낫다"가 아니라 **"같은 엔진·같은 장면에서 선택 규칙과 실패 처리만 바꿨을 때"**의 차이로 한정한다.
2. **왜 원본 그대로 비교하지 않았는지 이유를 적는다**: 원본은 CBS·구간 그래프·Safe Interval·Δ(s)까지 다르다. 통째로 비교하면 차이가
   선택 규칙 때문인지 엔진 때문인지 나눌 수 없다. 그래서 엔진을 고정하고 규칙만 바꾸는 것이 **통제된 비교**다(MAPF 논문에서 흔한 방식,
   LNS2도 여러 방법을 같은 코드 기반에 구현해 비교했다 — 27장 P7).
3. **Park에 가장 유리한 쪽으로 옮긴다**: 등록 순서는 CBS에 해당하는 **고정 먼저**를 대표 비교로 쓰고, 창 W는 10·20·40을 다 보여 준다
   (결과가 W에 거의 안 바뀜). 실패하면 같은 안전망을 준다.
4. **해석이 갈리는 부분은 민감도로 보인다**(남은 일): "구간"을 장애물 칸 하나가 아니라 **장애물 주변 r칸**으로 넓힌 변형(r = 1, 2).
5. **원본 코드 요청**: 논문에 코드 공개 여부가 없다. 저자에게 요청해 보고, 못 받으면 "코드가 공개되지 않아 규칙을 재구현했다"고 적는다.
6. **"위협 요인(threats to validity)" 문단**에 28.1.1 표의 다른 점을 그대로 적는다.

**남은 것**: 작업 시간을 켠 장면(기존 장면 s30_60, standing 장면)에서도 Park식을 돌려야 한다. Park식에는 작업 중인 로봇 규칙이 없지만,
우리 엔진에서는 근무표 규칙(작업 중 로봇은 못 움직임)이 모든 방법에 똑같이 적용된다(세계 모델은 공통, 20장 원칙 1).

**왜 W가 중요한가 (먼저 재 봤다)**: 영향받은 로봇이 장애물에 "몇 스텝 뒤에" 닿는지(`hit_offset_max` 열).
64×64에서는 **시나리오의 29~61%에서 20스텝보다 늦게 닿는 로봇이 있다**(32×32는 3~16%). 그래서 Park식은 "우리 Tier 0만"과 같지 않다.

**구현**
- `ReplanConfig::affected_window`(기본 −1 = 끔, 원래 동작 그대로). `ReplanResult::deferred_ids`, `event_times`.
- `PrioritizedPlanner::replan_windowed()`: 미룬 로봇이 창에 들어오는 시각마다 `replan()`을 다시 부른다.
- 벤치마크 `--affected-window W`, 새 열 `selective_events`(부른 횟수), `affected_n`, `hit_offset_max`.
- 테스트 3개(C++) + 파이썬 스모크 [10]. 변이 검사: 미룬 로봇을 앞부분만이 아니라 통째로 등록하게 바꾸면 2개가 실패.
- **기본 결과 불변 확인**: 7개 설정 400행씩 시간 열 빼고 다른 칸 0.

### 무엇을 말하나 (쉬운 해석) — 2026-11-19 사용자 지적으로 고침

> **정정**: Park은 CBS 기반이다. CBS로 "영향받은 로봇만 다시, 나머지는 경로 유지"를 하면 나머지 로봇의 경로는 다시 계획하는 **모든** 로봇에게
> 제약으로 주어진다 — 이건 사실상 **고정 먼저**와 같다. "섞어 등록"(앞 순서 재계획 로봇이 뒤 순서 고정 로봇을 모름)은 **PP로 옮겼을 때만
> 생기는 문제**일 가능성이 크다. 그래서 **Park에 공정한 비교는 "Park식 + 고정 먼저"**이고, "Park식 섞어"는 Park의 성능이 아니라
> **PP 기반 선택적 재계획에서 적는 순서가 얼마나 중요한지(C1)를 보여 주는 ablation**으로만 쓴다.

1. **공정한 비교(Park식 + 고정 먼저 vs 우리)**: 넓은 맵에서는 둘 다 50/50으로 같다. 좁은 통로에 로봇이 많으면 차이가 난다
   (200대 41 vs 48, 150대 46 vs 49, 100대 47 vs 50). 이 차이는 **Tier 1(③ 길 위 로봇 구조)**과 **미루지 않고 지금 처리하기**에서 온다(C2).
2. **ablation(같은 Park식 선택 규칙에서 적는 순서만 바꿈)**: 섞어 5 → 고정 먼저 41(통로 200대). PP로 "영향받은 로봇만 다시"를 하면
   적는 순서가 결과를 좌우한다는 우리 C1이, 우리 선택 규칙이 아닌 다른 선택 규칙(시간 창)에서도 성립한다. **이걸 "Park 방법이 실패한다"로 쓰면 안 된다.**
3. Park 논문의 "성공률 100%"와 직접 비교하지 않는다(엔진·지도·장애물·시행 방식이 다르다, 28.1.1).
4. **Park식은 "전체 재계획 이상" 보장이 없다.** 미룬 로봇을 나중에 다시 계획하다 실패하면, 안전망(전체 재계획)도 **나중 시각**에 돌게 된다.
   그때는 다른 로봇들이 이미 움직여서 지금 돌리는 전체 재계획보다 실패할 수 있다(예: 통로 200대 섞어 W40 성공 45 < 전체 재계획 46).
   우리 방법은 모든 영향받은 로봇을 **지금** 처리하므로 안전망도 지금 돈다 → 보장이 유지된다.
5. **늦어진 로봇 수**: Park식 섞어(200대 7.6대)는 안전망을 자주 써서 많고, 고정 먼저(4.5대)·우리(4.7대)는 비슷하다.
6. 충돌: 모든 방법·모든 시나리오에서 0.

## 28.3 다음: LNS2식 (설계 초안)

27장 P7(LNS2)을 장애물 재계획에 옮긴다. 같은 시나리오·같은 안전망.

1. 영향받은 로봇(우리 Tier 0과 같은 집합)의 경로를 지우고, 무작위 순서로 **충돌을 허용하는 A\***(충돌 수를 최소화, 같으면 짧은 길)로 다시 그린다.
   벽·새 장애물·작업 중 로봇(못 움직임)은 **절대 금지**, 다른 로봇과의 겹침은 **세기만** 한다.
2. 충돌 쌍이 0이 될 때까지: 이웃 8대를 고른다(충돌 기반 / 실패 기반 / 무작위, ALNS γ=0.1). 그 로봇들을 무작위 순서로 다시 그리고,
   충돌 쌍이 줄거나 같으면 받아들인다. 작업 중 로봇은 이웃에 넣지 않는다.
3. 시간 한도(또는 반복 한도) 안에 충돌 0을 못 만들면 **안전망(전체 재계획)**.
4. 비교 지표: 스스로 푼 수, 계산 시간(`--threads 1`), 다시 계획한(건드린) 로봇 수, 늦어진 로봇 수.

필요한 새 부품: 충돌 허용 A\*(시공간 A\*에 "충돌 수" 비용을 더한 모드), 충돌 그래프 계산, 반복 루프. 우리 엔진(PP + 시공간 A\*)은 그대로 쓴다.
