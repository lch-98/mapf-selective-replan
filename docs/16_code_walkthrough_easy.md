# 16. 바뀐 코드를 실행 순서대로 따라가기 — 예시 하나로 전부

> 작성: 2026-09-14. 문제를 고치기 전에, **지금 코드가 정확히 어떻게 움직이는지**를 한 예시로
> 처음부터 끝까지 따라간다. 이 문서의 중간값(몇 번째 칸에서 막혔는지, 누가 불려 왔는지 등)은
> 전부 **실제로 코드를 돌려서 확인한 값**이다(16.8절).

## 16.0 먼저 — 무엇이 바뀌었나

"고정 먼저 + 아이디어 3 + A\* 대기"라고 기억하고 있다면 **거의 맞다.** 다만 정확히 나누면 이렇다.

### (가) 새 방법 — 설정으로 켜고 끄는 것 (커밋 `2a97501`)

| 이름 | 한 줄 뜻 | 설정 스위치 |
|---|---|---|
| **고정 먼저** (fixed-first) | 원래 길로 가는 로봇을 장부에 **먼저 전부** 적는다 | `order = kFixedFirst` |
| **아이디어 3-1** 도달성 검사 | 다른 로봇이 없어도 못 가면 **바로 포기** | `check_reachability = true` |
| **아이디어 3-2** 구조 후보 고르기 | **가장 짧은 길 위의 로봇만** 부른다 | `rescue_selection = kShortestPathConflicts` |

세 스위치의 **기본값은 전부 "끔"(원래 방식)**이다([prioritized_planner.hpp:56-73](../core/include/mapf/prioritized_planner.hpp#L56-L73)).
켜야 새 방법이 된다. 벤치마크에서 "고정 먼저 + 아이디어 3"이라고 부른 것은 세 개를 모두 켠 것이다.

### (나) 버그 수정 — 어느 방법에서나 항상 적용되는 것

| 무엇 | 커밋 | 한 줄 뜻 |
|---|---|---|
| **A\* 도착 판정** | `154fcba` | 목적지에 닿아도, **나중에 누가 목적지를 지나갈 예정이면 도착으로 치지 않는다** |
| **경로 이어붙이기** (`splice_paths`) | `154fcba` | 과거 경로와 새 경로를 붙일 때 **빈 시각을 채운다** |
| **자리 맞바꾸기 검사** | `cf22720` | 옛 경로를 장부에 적을 때 **서로 자리를 바꾸는 충돌**도 거절한다 |

**"A\* 대기"에 대한 정정**: A\*는 **처음부터** 기다릴 수 있었다. 이웃 칸 목록에 "제자리"가 늘
들어 있다([map.cpp:51-57](../core/src/map.cpp#L51-L57)). 바뀐 것은 기다리기가 아니라
**"언제 도착했다고 인정하느냐"**다. 이 규칙이 바뀐 덕분에 A\*가 "잠깐 비켰다가/기다렸다가 늦게
도착하는 길"을 **찾아내게** 되었다. 그리고 이건 새 방법만의 기능이 아니라, 원래 방식·전체 재계획·
처음 계획(`plan`)에 모두 적용되는 **버그 수정**이다.

## 16.1 예시 준비

테스트 `ShortestPathRescueCallsOnlyAgentsOnTheRoute`와 같은 상황이다. 이 예시 하나에
**(가)의 세 가지와 (나)의 A\* 도착 판정·이어붙이기가 전부 등장한다.**

### 지도 (8×3)

```
         x:  0 1 2 3 4 5 6 7
  y=0:       # # # # . # # #      ← (4,0): 막다른 칸 하나
  y=1:       . # # . . . # #      ← (0,1): 막다른 칸 하나
  y=2:       . . . . . . . .
```

### 로봇 세 대 (우선순위 = 목록 순서)

| 순서 | 이름 | 출발 → 목적지 | 옛 경로 |
|---|---|---|---|
| 0번 (가장 중요) | **K** | (4,1) → (4,1) | 처음부터 목적지에 서 있음. 끝까지 머묾 |
| 1번 | **W** | (0,2) → (6,2) | 아래 줄 직진: (0,2)t0 (1,2)t1 (2,2)t2 (3,2)t3 (4,2)t4 (5,2)t5 (6,2)t6 |
| 2번 (가장 덜 중요) | **Z** | (0,1) → (0,1) | 처음부터 목적지에 서 있음. 끝까지 머묾 |

### 사건: t=3에 (4,2)에 장애물 X가 생긴다

```
  t=3 순간의 모습
         x:  0 1 2 3 4 5 6 7
  y=0:       # # # # . # # #
  y=1:       Z # # . K . # #
  y=2:       . . . W X . G .      W: 지금 (3,2), G: W의 목적지 (6,2)
```

W는 바로 앞이 막혔다. 오른쪽으로 가는 길은 가운데 줄 (3,1)→(4,1)→(5,1)뿐인데, **(4,1)에 K가 서
있다.** Z는 W의 길과 아무 상관이 없다.

호출: `planner.replan(agents, previous_paths, {(4,2)}, current_time=3)`
설정: 세 스위치 모두 켬(고정 먼저 + 3-1 + 3-2).

```

 ├─ 1단계  영향받은 로봇 찾기            → working = [W]
 ├─ 2단계  (3-1) 도달성 검사              → W는 다른 로봇만 없으면 갈 수 있음 → 통과

 ├─ Tier 0: try_replan_set(working=[W])
 │     ├─ 장부 비우고 장애물 적기

 │     ├─ K, Z 옛 경로 적기                → 성공
 │     ├─ W의 A*                           → 실패 (K가 길을 막음)
 │     └─ (3-2) 부를 로봇 칸 고르기         → (4,1)t5 한 칸만 넘김
 │
 ├─ 구조 로봇 추가                        → working = [W, K], rescued = [K]
 │
 ├─ Tier 1: try_replan_set(working=[W, K])
 │     ├─ 장부 비우고 장애물 적기
 │     ├─ 순서 정하기                      → [Z] 다음 [W, K]
 │     ├─ Z 옛 경로 적기
 │     ├─ W의 A*                           → 성공: K 자리를 t5에 지나감
 │     └─ K의 A* (새 도착 판정!)            → t5에 (4,0)으로 비켰다가 t6에 돌아옴
 │
 └─ 결과: Tier 1 성공, 다시 계획한 로봇 [W, K], 구조 로봇 [K], Z는 그대로
```

이제 한 단계씩 코드와 함께 본다.

## 16.3 1단계 — 영향받은 로봇 찾기

코드: [prioritized_planner.cpp:387-408](../core/src/prioritized_planner.cpp#L387-L408)

```cpp
for (const Agent& agent : agents) {                       // K, W, Z 순서로
    if (path_hits_obstacle(old_path, new_obstacles, current_time)) {
        working_ids.push_back(agent.id);
        ...(2단계: 도달성 검사)...
    }
}
```

`path_hits_obstacle`([180-193줄](../core/src/prioritized_planner.cpp#L180-L193))은 "옛 경로가
**지금(t=3) 이후에** 장애물 칸을 밟는가?"를 본다.

| 로봇 | t=3 이후 위치 | 장애물 (4,2)를 밟나? |
|---|---|---|
| K | 계속 (4,1) | 아니오 |
| W | t4에 **(4,2)** | **예** → working |
| Z | 계속 (0,1) | 아니오 |

→ `working_ids = [W]`. **이 목록이 "다시 계획할 로봇" 명단**이다. 명단에 없는 로봇(K, Z)은 "고정
로봇"이라 옛 경로를 그대로 쓴다.

## 16.4 2단계 — (아이디어 3-1) 도달성 검사

코드: [prioritized_planner.cpp:399-406](../core/src/prioritized_planner.cpp#L399-L406)

```cpp
if (replan_config_.check_reachability) {
    Cell here = position_at(old_path, current_time);            // W의 지금 위치 (3,2)
    std::vector<Cell> route = static_shortest_path(map_, here, agent.goal, new_obstacles);
    if (route.empty()) return std::nullopt;                      // 길이 아예 없음 → 포기
    int earliest_arrival = current_time + route.size() - 1;
    if (earliest_arrival > config_.max_timestep) return std::nullopt;  // 시간 안에 못 감 → 포기
}
```

**질문: "다른 로봇이 하나도 없다면 W는 목적지에 갈 수 있나?"**

- `static_shortest_path`([44-79줄](../core/src/prioritized_planner.cpp#L44-L79))는 **시간 없는
  평범한 BFS**다. 벽과 새 장애물만 보고, 로봇은 전혀 보지 않는다.
- 결과: `(3,2) → (3,1) → (4,1) → (5,1) → (5,2) → (6,2)` (6칸, 5번 이동).
- 가장 빨리 도착하는 시각: 3 + 6 − 1 = **t=8**. 한도(`max_timestep` = 256) 안이다.

→ **통과.** W는 로봇만 없으면 갈 수 있다. 막는 건 장애물이 아니라 **로봇 K**다.

**만약 실패했다면**: 이 로봇은 누구를 불러와도, 전체 재계획을 해도 절대 못 간다. 그래서 Tier와
안전망을 건너뛰고 바로 `nullopt`(실패)를 돌려준다. **결과는 안 바뀌고 시간만 아낀다.**

**참고**: 구조 로봇은 이 검사를 하지 않는다. 구조 로봇의 옛 경로는 장애물을 안 밟으므로, 그 옛
경로 자체가 "갈 수 있다"는 증거이기 때문이다.

## 16.5 Tier 0 — 첫 번째 시도

코드: `replan`의 반복문 [418-469줄](../core/src/prioritized_planner.cpp#L418-L469)이
`try_replan_set`([208-321줄](../core/src/prioritized_planner.cpp#L208-L321))을 부른다.

### ① 장부를 비우고 장애물을 적는다 (215-216줄)

```cpp
table_.clear();
reserve_new_obstacles(new_obstacles, current_time);
```

(4,2)를 **t3부터 t256까지** 예약한다. 주인은 **-1**("로봇 아님")이다. 그래서 나중에 "누가
막았나?"를 추적할 때 장애물은 구조 로봇 후보에서 저절로 빠진다.

### ② 처리 순서를 정한다 (224-246줄) ← **고정 먼저의 핵심**

```cpp
if (replan_config_.order == ReplanOrder::kFixedFirst) {
    for (agent : agents)   if (!in_working(agent.id)) order.push_back(agent);  // 1) 고정 로봇 전부
    for (id : working_ids) order.push_back(그 로봇);                            // 2) working_ids 순서
} else {
    for (agent : agents)   order.push_back(agent);                              // 원래: agents 순서 그대로
}
```

| 방식 | 이 예시에서 처리 순서 |
|---|---|
| 원래 방식 (`kPriority`) | K(고정) → **W(A\*)** → Z(고정) |
| 고정 먼저 (`kFixedFirst`) | K(고정) → Z(고정) → **W(A\*)** |

**바뀐 건 순서 목록뿐이다.** 아래 반복문(248-318줄)은 두 방식이 한 글자도 다르지 않다.
`in_working`은 "명단에 있나?"만 확인할 뿐, **순서나 우선순위와는 상관없다.**

### ③ 고정 로봇의 옛 경로를 적는다 (252-275줄)

```cpp
if (!is_working) {
    if (!register_path(agent.id, old_path)) {        // 거절되면
        *out_blocked_owner = agent.id;               //   "나 거절당했어"라고 알리고
        return std::nullopt;                         //   이번 시도 실패
    }
    continue;
}
```

`register_path`([86-136줄](../core/src/prioritized_planner.cpp#L86-L136))가 하는 일:
1. 경로의 모든 (칸, 시각)을 예약한다. 이미 남의 것이면 **거절**한다.
2. 모든 이동(칸→칸)을 예약한다. 누가 반대로 오고 있으면(자리 맞바꾸기) **거절**한다. ← (나)의 버그 수정
3. **Tail**: 도착한 칸을 도착 시각부터 t256까지 예약한다. 이미 남의 것이면 **거절**한다.

- K: (4,1)을 t0~t256 예약 → **성공**
- Z: (0,1)을 t0~t256 예약 → **성공**

고정 먼저에서는 **여기서 거절이 원리상 안 생긴다.** 장부에는 장애물과 다른 고정 로봇만 있는데,
옛 경로끼리는 원래 서로 안 부딪혔고, 장애물을 밟는 로봇은 이미 working이 되었기 때문이다.

### ④ W의 A\*를 돌린다 (284-288줄)

```cpp
Cell here = position_at(old_path, current_time);    // (3,2)
AStarResult astar_result = astar.search_with_diagnostics(here, agent.goal, current_time);
```

A\* 안에서([space_time_astar.cpp:74-159](../core/src/space_time_astar.cpp#L74-L159)):
- 먼저 **목적지 (6,2)가 마지막으로 예약된 시각**을 구한다(83-86줄). 아무도 예약하지 않았다 →
  "언제 도착해도 된다".
- 탐색: 오른쪽 (4,2)는 장애물이다. 가운데 줄로 올라가도 (4,1)은 **K가 t256까지** 차지하고 있다.
  기다려도 K는 안 비킨다(K는 고정 로봇이라 옛 경로 = 영원히 머묾).
- 그래서 A\*는 **갈 수 있는 모든 (칸, 시각)을 t256까지 다 뒤진 뒤** 실패한다. 이게 15장의 문제 1
  ("포기가 늦다")이 작은 규모로 나타난 모습이다.
- 뒤지는 동안 막혔던 칸을 전부 `blocked_attempts`에 적는다. 실제로 **755개**가 기록됐고, 그 칸들의
  주인은 **장애물(-1), K, Z**였다.

**왜 Z가 들어가나?** W는 오른쪽이 막히자 왼쪽으로도 헤매다가, (0,2)에서 위 칸 (0,1)로 가려다
**t7에 Z에게 막혔다.** W의 길과 아무 상관없는데도 "막혀 본 칸"에 들어간 것이다.

### ⑤ (아이디어 3-2) 누구를 부를지 칸을 고른다 (290-310줄)

```cpp
*out_blocked = astar_result.blocked_attempts;        // 기본: 막혀 본 모든 칸 (755개)
if (rescue_selection == kShortestPathConflicts) {
    conflicts = shortest_path_conflicts(here, goal, new_obstacles, current_time);
    if (conflicts 중에 아직 working이 아닌 로봇이 한 대라도 있으면)
        *out_blocked = conflicts;                    // 3-2: 최단 경로와 부딪히는 칸만
}
return std::nullopt;
```

`shortest_path_conflicts`([323-355줄](../core/src/prioritized_planner.cpp#L323-L355))는
**2단계에서 본 그 BFS 최단 경로**를 **쉬지 않고** 간다고 보고, 시각을 붙인다.

| 칸 | (3,2) | (3,1) | (4,1) | (5,1) | (5,2) | (6,2) |
|---|---|---|---|---|---|---|
| 시각 | t3 | t4 | **t5** | t6 | t7 | t8 |
| 장부에 누가? | (출발 칸, 검사 안 함) | 없음 | **K** | 없음 | 없음 | 없음 |

세 가지를 검사한다.
1. **칸 충돌**: 그 시각에 그 칸을 누가 예약했나? → **(4,1)t5 = K** ✔
2. **자리 맞바꾸기**: 내가 A→B로 갈 때 누가 B→A로 오나? → 없음
3. **도착 후 머묾**: t8 이후 목적지 (6,2)를 누가 쓰나? → 없음

→ `conflicts = [(4,1)t5]`. 주인 K는 아직 working이 아니므로 "새 후보 있음" → **이 한 칸만
넘긴다.** (3-2를 끄면 755칸이 그대로 넘어간다.)

**예외 규칙**(307줄): 부딪히는 로봇이 전부 이미 working이면(새로 부를 로봇이 없으면) 755칸짜리
원래 목록을 그대로 둔다. 안 그러면 아무도 못 부르고 끝나 버리기 때문이다.

## 16.6 구조 로봇 추가 — Tier 0이 실패한 뒤

코드: [prioritized_planner.cpp:437-468](../core/src/prioritized_planner.cpp#L437-L468)

```cpp
if (tier == max_escalation_tiers) break;             // 더 넓힐 기회가 없으면 안전망으로

// (a) 등록이 거절된 로봇 자신 — 고정 먼저에서는 비어 있다
if (blocked_owner.has_value()) { ... }

// (b) 넘겨받은 칸마다 주인을 찾아서 추가
for (cell : blocked) {
    owner = table_.get_owner(cell);
    if (주인 없음 || 장애물(-1) || 이미 working) continue;
    working_ids.push_back(owner);
    rescued_ids.push_back(owner);
}
if (!added_any) break;                               // 아무도 못 불렀으면 안전망으로
```

- 넘겨받은 칸: (4,1)t5 → 주인 **K** → 추가.
- `working_ids = [W, K]`, `rescued_ids = [K]`.

**중요한 점 두 가지**
- **여기서 한 칸의 주인만 부르는 게 아니다.** 넘겨받은 칸 목록의 주인을 **전부** 부른다. 이
  예시는 칸이 하나라서 K 한 대다. 3-2를 끄면 755칸의 주인인 **K와 Z 둘 다** 불려 온다.
- **K는 W 뒤에 붙는다.** `push_back`이니까 명단의 맨 끝이다. 이게 다음 시도에서 "K가 W 다음에
  계획된다"의 이유다.

## 16.7 Tier 1 — 두 번째 시도

`try_replan_set`을 **처음부터 다시** 부른다. 이어서 하는 게 아니라 **장부를 비우고 새로** 한다.

### ① 장부 비우기, 장애물 적기 — Tier 0과 같다

### ② 순서 정하기

- 고정 로봇: **Z만** (K는 이제 working이다)
- working_ids 순서: **W → K**
- 최종 순서: **Z → W → K**

### ③ Z 옛 경로 적기 → 성공

### ④ W의 A\* — 이번에는 성공

장부에 K가 **없다**(K는 아직 계획 전). 그래서 W는 (4,1)을 지나가는 최단 경로를 찾는다.

```
W 새 경로: (3,2)t3 (3,1)t4 (4,1)t5 (5,1)t6 (5,2)t7 (6,2)t8
```

**이어붙이기**(314줄, `splice_paths` [22-38줄](../core/src/prioritized_planner.cpp#L22-L38)):
옛 경로의 과거 부분 (0,2)t0 (1,2)t1 (2,2)t2 + 새 경로 → 등록 성공.

### ⑤ K의 A\* — **새 도착 판정**이 일하는 곳

K는 지금 (4,1)에 있고 목적지도 (4,1)이다. 이미 도착한 상태에서 다시 계획하는 것이다.

A\* 시작(83-86줄): 목적지 (4,1)이 마지막으로 예약된 시각 = **t5**(W가 지나감).

탐색([115-128줄](../core/src/space_time_astar.cpp#L115-L128)):

```cpp
if (current_xy == goal) {
    if (current->cell.t > goal_last_reserved) {   // t5보다 뒤여야 도착 인정
        return 경로;
    }
    // 아니면: 도착으로 치지 않고 계속 탐색
}
```

| 시각 | K의 상태 | 판정 |
|---|---|---|
| t3 | (4,1) — 목적지 위 | 3 ≤ 5 → **도착 아님**, 계속 |
| t4 | (4,1)에서 기다림 | 4 ≤ 5 → 도착 아님, 계속 |
| t5 | (4,1)은 W 차지 → **(4,0)으로 비킴** | 목적지 아님 |
| t6 | (4,1)로 돌아옴 | 6 > 5 → **도착 인정!** |

```
K 새 경로: (4,1)t3 (4,1)t4 (4,0)t5 (4,1)t6
```

**만약 옛 도착 판정이었다면?** A\*는 t3에 "목적지에 있네" 하고 바로 `[(4,1)t3]`를 돌려줬을 것이다.
그러면 `register_path`의 Tail이 (4,1)을 t3~t256 예약하려다 **t5에서 W와 부딪혀 거절**된다(316줄).
그러면 이 시도는 실패하고, 이 실패에는 "누가 막았는지" 정보도 없다. **비켜 주면 풀리는 상황인데
못 푸는 것**이다. 이게 `154fcba`에서 고친 버그다.

**이어붙이기**: K의 옛 경로는 `(4,1)t0` 하나뿐이다(처음부터 도착해 있었으니까). 그래서 과거 부분이
t0에서 끝나고, **t1·t2가 비어 있다.** `splice_paths`가 이 빈 시각을 "목적지에 머묾"으로 채운다
(28-33줄).

```
K 최종 경로: (4,1)t0 (4,1)t1 (4,1)t2 | (4,1)t3 (4,1)t4 (4,0)t5 (4,1)t6
             └── 과거(채워 넣은 t1·t2 포함) ──┘ └──────── 새 경로 ────────┘
```

빈 시각을 안 채우면 "경로의 i번째 칸 = 시각 i"라는 약속이 깨져서, `position_at`이나 GUI가 로봇
위치를 엉뚱하게 읽는다. 이것도 `154fcba`에서 고친 버그다.

### ⑥ 전부 성공 → 결과 반환 (428-435줄)

| 항목 | 값 |
|---|---|
| `escalation_tier` | 1 (두 번째 시도에서 성공) |
| `replanned_ids` | [W, K] |
| `rescued_ids` | [K] |
| Z | **옛 경로 그대로** (안 건드림) |

## 16.8 같은 예시, 설정만 바꿔서 — 실제 실행 결과

임시 추적 프로그램으로 실제 `replan`을 세 설정으로 돌린 결과다(프로그램은 확인 후 삭제).

| 설정 | 결과 | 불려 온 로봇 | Z |
|---|---|---|---|
| 원래 방식 (`kPriority` + 막혀 본 모든 칸) | **실패** (안전망도 실패) | — | — |
| 고정 먼저 + 막혀 본 모든 칸 | Tier 1 성공 | **K, Z** | 불려 왔지만 결국 제자리 → **헛부탁** |
| 고정 먼저 + 아이디어 3 | Tier 1 성공 | **K만** | 그대로 |

### 원래 방식은 왜 실패하나?

순서가 K → W → Z다.
1. Tier 0: K(고정) 적기 → W의 A\* 실패(K가 막음) → K를 구조 로봇으로 부름.
2. Tier 1: 순서는 여전히 **K → W**(원래 방식은 agents 순서 그대로). K가 **먼저** 계획하는데, 장부에
   W가 아직 없으니 "그냥 제자리에 있으면 되네" 하고 머문다 → W는 또 막힘.
3. 더 부를 로봇이 없다 → 안전망(전체 재계획) → 거기서도 K → W 순서라 똑같이 실패.

이게 10·11장에서 말한 **(b) 구조 로봇 문제**다. 구조 로봇 K가 막힌 로봇 W보다 **앞**에 계획돼서,
W를 모른 채 같은 선택을 한다. 고정 먼저는 K를 W **뒤**에 두어서 이 문제를 없앴다.
