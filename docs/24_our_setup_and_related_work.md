# 24. 우리 실험은 무엇을 고정했고, 기존 연구와 무엇이 다른가

> 2026-11-18. 일정 6번(비교 기준 구현)을 시작하기 전에 정리한다. 6번에서 Park 2026식·LNS2식을 구현할 때
> "무엇을 똑같이 맞추고, 무엇만 바꿔서 비교하는지"의 기준이 이 문서다.
> 근거: 07장(연구 위치), 15장(기존 연구 비교), 12·13장(우리 방법), 17장(작업 시간), 18장(엔진), 20장(실험 원칙), 오늘 실험(21~23장).
> **주의**: 기존 연구 내용은 지금까지의 짧은 검색(15장) 기준이다. 6′ 문헌 조사에서 다시 확인해야 하는 곳은 ⚠로 표시했다.

---

## 24.0 한 장 요약

- 우리 방법 = **PP(고정 우선순위) + 시공간 A\*** 위에서, **"어떤 로봇을, 어떤 순서로 다시 계획하나"만** 바꾼 것이다.
- 부품은 셋이고, 논문 실험에서는 **셋 다 켠다**: ① 고정 로봇 먼저 적기, ② 도달 확인(BFS), ③ 길 위의 로봇만 구조.
  효과는 거의 ①에서 나온다(64×64 안전망 없이 성공 243 → 394), ③은 ① 위에서 조금 더(394 → 397, 다시 계획한 로봇 6 → 4대),
  ②는 지금 벤치마크에서 효과 0(길이 완전히 끊기는 장면이 없음).
- **"영향받은 로봇만 다시 계획"과 "나머지 고정 + 일부만 다시 계획"은 새롭지 않다**(Park 2026, OID / LNS 계열).
  우리가 주장할 수 있는 건 **그게 실패했을 때의 처리**(실패 원인 분석 + 고정 먼저 + 원인 로봇만 구조 + 안전망)와
  **작업 중인 로봇을 움직이지 않는 규칙을 실행 중 재계획에 넣은 것**, 그리고 **성공률을 절대 잃지 않으면서 10~20배 빠름**을 보인 것이다.

## 24.1 우리 실험에서 고정한 것 (모든 방법에 똑같이)

### 1) 세계 모델

| 항목 | 고정값 | 비고 |
|---|---|---|
| 지도 | 4방향 격자. 32×32 / 64×64, 넓은 맵(open)·좁은 통로 맵(corridor) | `tools/benchmark_maps.hpp` |
| 시간 | 이산 시간. 한 스텝에 한 칸 이동 또는 제자리 대기 | 실제 로봇은 실행 계층이 필요(8번) |
| 충돌 | 같은 시각 같은 칸 금지, 자리 맞바꾸기 금지 | |
| 도착 후 | 목적지에 계속 머문다(꼬리 예약). 작업 시간 동안은 **절대 안 움직임**, 끝나면 주차(비켜 줄 수 있음) | 17장 |
| 장애물 | 실행 중 1~3칸이 **나타나서 머문다**. 그중 하나는 누군가의 다음 칸 | 사라지는 장애물·움직이는 장애물은 범위 밖(09장) |
| 시간 상한 | `max_timestep = 256` | |

### 2) 엔진 (모든 방법이 같은 엔진을 쓴다, 20장 원칙 1)

| 부품 | 고정값 |
|---|---|
| 고수준 | **PP(고정 우선순위)**: 로봇을 정해진 순서로 한 대씩 계획하고 장부에 적는다. 앞 로봇은 뒤 로봇을 모른다 |
| 저수준 | **시공간 A\***, 맨해튼 휴리스틱, 대기 동작 포함 |
| 동점 규칙 | f 작은 쪽 → g 큰 쪽 → 먼저 넣은 쪽(18장). 민감도 실험으로 결론이 이 선택에 기대지 않음을 확인(21.8) |
| 속도 최적화 | 장부가 굳은 뒤 같은 칸 한 번만 확인(18장, 결과 불변) / BFS 메모장(22장, 결과 불변) |

### 3) 비교 기준 — 전체 재계획

- 지금 위치에서 **모든 로봇**을 같은 PP 순서로 다시 계획한다. 작업 중인 로봇은 작업 끝까지 그대로(17장 규칙 동일).
- 우리 방법의 **안전망과 똑같은 함수**다. 그래서 우리 방법의 성공률은 구조적으로 전체 재계획 이상이다
  (9,200 시나리오에서 "전체 재계획만 성공" 0건).
- 3D(Gazebo)·실제 로봇 실험에서는 **이것과만** 비교한다(2026-11-18 결정). Park식·LNS2식은 2D에서만.

### 4) 우리 방법의 설정

| 스위치 | 논문 실험 | 하는 일 | 효과(64×64, 400 시나리오) |
|---|---|---|---|
| ① `order = fixed-first` | **켬** | 다시 계획하지 않는 로봇의 길을 장부에 먼저 적고, 그다음 막힌 로봇 → 구조 로봇 순으로 계획 | 안전망 없이 성공 243 → **394** |
| ② `check_reachability` | **켬** | 처음 영향받은 로봇마다, 다른 로봇이 없어도 못 가면(BFS) 바로 실패 | 이 벤치마크에선 0(결과 불변, 길이 끊기는 장면에서만 시간 절약) |
| ③ `rescue = shortest path` | **켬** | A\*가 실패한 로봇의 "로봇 없을 때 가장 짧은 길" 위에 있는 로봇만 구조 | ①과 함께일 때 394 → **397**, 다시 계획 6 → 4대, 느린 5% 213 → 127 ms. ① 없이는 효과 0 |
| `max_escalation_tiers` | **1** | Tier 0 → Tier 1 → 안전망 | |
| 양보 요청 | **끔** | 늦어진 로봇을 위해 서 있는 로봇에게 비켜 달라고 한 번 더 | 효과 작음, 시간 +20%(19장) → ablation 한 줄 |
| **작업 시간 규칙**(17장) | **항상 켬**(모델의 일부) | 로봇은 목적지에 도착하면 작업 시간 동안 **절대 안 움직이고**, 작업이 끝나면 주차(구조로 불리면 비켜 줌). 재계획은 근무표를 받아 작업 중 로봇을 작업 끝까지 고정 | 기존 장면에선 결과가 0.5~7%만 바뀜. 우회로에 서 있는 로봇 장면(standing)에선 전체 재계획 최대 37%, 우리 4~5%(23장) |

작업 시간 실험 수준: 0 / U[1,10] / U[30,60](로봇마다 정수 균등, 별도 난수라 켜도 배치·장애물 그대로). 전체 재계획에도 **같은 작업 시간 규칙**을 적용한다(공정성).

### 5) 시나리오와 지표

- 처음 계획이 성공하고, 장애물이 실제로 누군가를 막는 시나리오만(거른 비율은 `plan_attempts`로 보고).
- 같은 씨앗 = 같은 시나리오, 짝지어 비교. 작업 시간은 별도 난수(켜도 배치·장애물 그대로).
- 본문 지표: 성공률, **안전망 없이 성공**, 다시 계획한 로봇 수, 목적지 밖 시간, 늦어진 로봇 수, 시간(중앙값·p95·최대),
  **계산 시간을 포함한 총 늦어짐**(23장). "바뀐 로봇 수"는 부록(동점 규칙에 민감).

## 24.2 기존 연구와 비교

### 한눈에

| 연구 | 무엇을 다시 계획하나 | 다시 계획이 **실패하면** | 작업 중 로봇 | 우리와 관계 |
|---|---|---|---|---|
| **전체 재계획**(교과서적 기준) | 전부 | — | (구현마다 다름) | 우리 비교 기준이자 안전망 |
| **Park 외 2026** (*Sensors*) | 장애물 구간에 곧 들어갈 로봇만, 나머지 그대로. CBS 기반, 연속 구간 모델, 공장 10~100대 | 논문에 없음(성공률 100%로 보고) | **작업 시간 없음**(작업을 마치면 바로 새 작업, 15.10) | **발상이 가장 가깝다.** 6번에서 "Park식 선택 규칙"을 우리 엔진 위에 구현해 비교 |
| **OID** (Švancara 외 2019, Online MAPF — 예전에 "OID"라고 잘못 적음, 27장 P6) | 영향받은 로봇부터, 새 경로가 다른 로봇과 부딪히면 그 로봇도 | **경로가 아예 안 나오는 실패는 못 다룸**(경로가 나온 뒤에만 검사) | 다루지 않음 | 우리 Tier 1이 그 빈틈(경로 자체가 안 나옴)을 다룬다 |

| **FlexSIPP** (Hanou 외 2026) | 로봇이 **지연**되면 그 로봇 하나 재계획(장애물 아님) | — | 언급 없음 | 지연 대응. 작업 시간 X |

### 작업 시간을 고려한 연구가 있나? (15장 15.10의 짧은 검색 기준)

| 구분 | 연구 | 작업 시간 | 실행 중 예기치 않은 장애물 재계획 |
|---|---|---|---|
| 실행 중 장애물 재계획 | **Park 2026** (가장 가까움) | **없음** | 있음 |
| 오프라인 계획 | MCPF with Heterogeneous Task Duration (Zhang 외 2023/24), Schedule-Constrained MAPF (SoCS) | **있음** | 없음(지연 시 재계획 언급 정도) |
| 창고 lifelong | MAPD, RHCR, Jiang 외 2024 | 보통 0 / 없음 | 없음(지도 변화는 과제로 언급) |
| 지연 대응 | FlexSIPP | 언급 없음 | 장애물 아님, 로봇 지연 |

**정리**: 작업 시간 자체는 오프라인 계획 연구에서 이미 다룬다(새롭지 않다). 하지만 **"실행 중 예기치 않은 장애물 재계획"과
"작업 시간(작업 중인 로봇은 못 움직임)"을 함께 다룬 연구는 짧은 검색에서 찾지 못했다.** 논문에서는 "작업 시간을 처음 고려했다"가 아니라
**"실행 중 선택적 재계획에서 작업 중인 로봇을 움직이지 않는 규칙을 넣고, 그 영향이 나타나는 장면(standing)에서 평가했다"**처럼
구체적인 조합으로 말해야 안전하다. ⚠ 6′ 문헌 조사(특히 MAPD의 작업 시간 변형, 온라인 MAPF + 처리 시간)로 다시 확인.

### 무엇이 같고 무엇이 다른가 — 부품별로

| 우리 부품 | 비슷한 기존 것 | 같은 점 | 다른 점 |
|---|---|---|---|
| Tier 0: 영향받은 로봇만 | Park 2026, OID | 발상 동일 | 없음 — **새롭다고 주장하지 않는다** |
| ① 고정 로봇 먼저 | LNS 계열(나머지 고정) | 구조 동일 | 우리는 **"PP 선택적 재계획이 실패하는 이유의 99%가 적는 순서"**라는 측정(11·12장)과 함께, 실행 중 재계획에 적용. 기법 자체는 겹친다 |
| Tier 1: 원인 로봇 구조 | OID(부딪히면 추가), IC/WinC-MAPF(단계 확장) | 넓혀 간다 | OID는 경로가 안 나오는 실패를 못 다룸. 우리는 **A\*가 실패해도** 원인 로봇을 찾는다 |
| ③ 길 위의 로봇만 구조 | LNS2의 충돌 기반 이웃 선택 | 비슷한 발상 | 실패한 로봇의 "로봇 없을 때 가장 짧은 길"을 기준으로 결정론적으로 고른다. 옛 방식(막혀 본 모든 칸)보다 헛부탁 44~65% → 5~19%(15장) |
| ② 도달 확인 | (흔한 사전 검사) | — | 새롭지 않다. 결과를 바꾸지 않고 시간만 아끼는 장치 |
| 작업 시간 규칙 | MCPF 등(오프라인) | 작업 시간 모델 | **실행 중 재계획**에서 작업 중 로봇은 안 움직이고, 구조로 불려도 작업 끝난 뒤 비킨다 |
| 안전망 | (일반적) | — | 덕분에 **성공률이 전체 재계획보다 절대 낮지 않다**는 보장 |

### 그래서 논문에서

- ❌ 쓰면 안 되는 주장: "영향받은 로봇만 다시 계획하는 새 방법", "다른 로봇을 고정하고 일부만 다시 계획하는 새 방법",
  "기존 MAPF는 물류 현장을 고려하지 않았다".
- ✅ 쓸 수 있는 주장(데이터 있음):
  1. PP 기반 선택적 재계획의 실패는 대부분 **적는 순서** 때문이고(Tier 0 실패의 99%), 고정 먼저로 거의 사라진다
     (안전망 없이 성공 243 → 397 / 400, 독립 검사 118 / 120).
  2. A\*가 실패해도 **실패한 로봇의 가장 짧은 길 위의 로봇만** 불러 넓히면 헛부탁이 크게 준다.
  3. 안전망 덕분에 **성공률은 전체 재계획 이상**이면서 **8~21배 빠르고**(한 번에 하나씩 잰 중앙값, 64×64), 동점 규칙을 바꿔도 결론이 유지된다.
  4. 계산 시간까지 손해로 넣으면, **빠른 로봇(한 칸 0.5초 이하) + 로봇 150대 이상**에서 로봇당 늦어짐이 크게 준다
     (64×64 200대, 0.25초: 1.08 → 0.16). 단 **한 칸 1초 이상이면 차이가 거의 없다**(23장) — 이 조건을 숨기지 말고 함께 써야 한다.
  5. 작업 중인 로봇을 움직이지 않는 규칙을 실행 중 재계획에 넣었다. 우회로에 서 있는 로봇이 있는 장면(standing)에서는
     이 규칙 때문에 전체 재계획의 결과가 최대 37% 시나리오에서 바뀌고, 우리 방법은 4~5%에서만 바뀐다(23장). 작업 시간을 0으로 두면
     이런 장면에서 실제로는 실행할 수 없는 계획이 나온다.
- ⚠ 6번에서 꼭 확인할 것: **Park식이 실제로 얼마나 자주 실패하는지**(우리 원래 방식처럼 자주 실패한다면 주장 1이 강해지고,
  거의 실패하지 않는다면 우리 기여는 "속도·작업 시간 규칙" 쪽으로 좁아진다), **LNS2식 수리와 시간·성공률 비교**.
